# ADR 0039：在固定输出上限下比较批量读取路径数

- 日期：2026-11-07
- 状态：Accepted（先离线开发，效果未验证）
- 依据：用户目标“先解决交互可学习性，再继续比较 RL 算法”，H2完整负面结果与离线请求重放。

实施后更新：[H3完整结果](../trainable-agent-rl/batch-limit-results.md)两组均4/16，
八项组形成两个家族的反馈修复，但综合门槛未过；保留原准入条件和默认四项配置。

## 决策依据

H2有9次批量读取因超过4路径被拒；现有Pydantic错误已经给出“最多4项”的明确提示。
离线在原始任务文件上重放这9个请求，可信driver仅将上限改为8时，7次通过、2次仍路径
拒绝；通过的7次中6次触发5000字符截断。该结果不能证明模型会节约Token或修复成功，
也不能冒充历史修改工作区的重跑。

路径项数4是实验约束；实际权限由固定白名单、真实路径校验和容器隔离控制，输出仍有
5000字符总上限。因此选择只改变最大路径数4→8，不同时改错误反馈、Prompt、文件权限、
输出额度或模型。需报告截断、后续补读和Context失败，防止把更少拒绝等同于有效信息更多。

## 实现及兼容

在独立实验包增加显式 `batch_read_eight`，默认single_read与原batch_read四项行为不变。
仅新模式使用八项Schema/说明和可信Session配置；模型不能通过参数更改上限。
容器driver对可信上限仅接受4或8；模型路径仍全量预检、非法整批拒绝，无静默分割、
自动重试或补采样。核心Loop、插件系统、权限和训练依赖不变。

H3固定完整32条：原8题×2seed×两种上限，两组均提供read_files，保留原Prompt、初始
策略及H2全部资源额度。保留正配对成功率差、≥2个八项组独有成功配对、≥2个八项组
反馈修复家族的开发门槛，含实际批量读取早于失败反馈及私有候选复评。不降低H2门槛。

## 阶段、费用与退出

当前唯一阶段先完成真实Docker双上限/截断/路径/无修改验收、脚本反馈路径、精确渲染、
评分和资金拒绝契约；再按新冻结协议核对源码、报价及完整队列资金。累计50元不变，
当前保守44.013元、可用5.987元；H3需预留2.88元，不能据余量自动授权训练。

若只消除参数拒绝而增加截断或未改善反馈修复，不进入RL，不继续自动放宽约束。
后续训练与算法比较仍需新家族、初始化/归一化/剂量控制及完整评测资金。
回退新模式即可，旧数据与旧源码归档冻结；原H2报告不重写成新版本实测。

详细协议见[H3路径上限方案](../trainable-agent-rl/batch-limit-plan.md)。
