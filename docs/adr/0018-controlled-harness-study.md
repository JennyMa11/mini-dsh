# ADR 0018：公开修复题上的受控 Harness 实验

- 状态：Accepted
- 日期：2026-10-03

公开题通过率只能证明任务完成，不能证明 Context、输出管理、恢复和权限功能。保留原 12 题 public-lite 基线，增加独立的 `harness-study check/run/rescore`，先验证功能，再做单变量配对试验。模型与默认运行配置不随结果调整。

固定 20 个功能 case，复用有明确刺激与断言的契约/集成测试；真实容器探针补充网络、cgroup、挂载与 Docker socket 边界。测试通过不自动表示所有操作系统攻击都已覆盖。安全结果与公开修复成功率分别报告。

选六道已锁定的 HumanEvalFix-docs Python/JavaScript 公开修复题，每组两题、两变体、两次重复，AB/BA 顺序，共 24 次串行运行。上下文使用完整工具轮次的生成历史；输出使用工作区日志；恢复使用经过 Tool Runtime 的三个真实失败调用。刺激由评测器确定，脚本响应零模型 Token，与真实 API 调用分别记录。它们是公开题的受控环境条件，不作为新的通用 Benchmark 排名。

两种上下文共用 8192 字符估算 Token 的准入边界，BudgetContext 的选择预算为 4096。该估算不代表 DeepSeek 的真实输入上限。输出两组均启用同一种规范化，仅改变输出字符上限；恢复两组均启用 Local-first，仅改变错误恢复开关。禁止将不同题组的表现当作变量效应。

每次 8000 Token，24 次名义 192000，留 48000 给已经发出请求的超额；整轮上限 240000。无法收回已发出的请求，实际超额必须记账；未知 usage 停止整轮，未运行行继续进入分母。固定输出上限 1024，通过显式 adapter 参数发送；严格 usage 校验仅在本实验启用，其他入口默认行为不变。

墙钟在步骤边界、模型返回后和每个工具执行前检查。本实验额外以 180 秒取消包络覆盖在途操作；取消保留原 `cancelled` Trace 终态与未知 usage，不能改写成正常完成。回归测试发现并修复模型返回时已超时仍执行工具的路径；没有修改步数预算的“本步仍可执行工具”语义。

沿用 [ADR 0015](0015-public-container-benchmark.md) 的可信宿主编排例外：数据读取、启动固定 argv 的 pytest 与 Docker、注入题目、捕获候选、启动独立验证器由 Benchmark adapter 执行；模型只能调用容器内 ShellTool，经 Tool Runtime 与 Permission System。模型容器不挂载主机目录、密钥、Docker socket；网络关闭，原生架构，1 CPU / 1 GiB / 128 PIDs。pytest 只运行源码中登记的节点，不接受模型生成的命令。

源码、测试、协议、锁文件、镜像与门禁证据在读取密钥前校验和冻结；每次运行后保存 Trace、候选哈希、独立验证收据、usage 来源、约束证据与汇总。重评分只读冻结事实，校验审计哈希，将新评分器哈希及变更行写入新目录，禁止覆盖基线或用 API 重跑失败题。

替代方案包括直接扩大 SWE-bench、引入 LLM judge 或使用更多合成题；前者超过本机资源，后两者增加 Token 和评分偏差。本轮采用可执行规则，未来扩展独立公开任务和重复数时创建 v2 协议，不就地修改 v1。
