# ADR 0033：CLI 模型选择与配置翻译的显式依赖

- 状态：Accepted
- 日期：2026-11-05

## 背景

完成参数、报告与 work 配置拆分后，cli.py 仍有 1289 行。模型选择同时处理参数优先级、
提供方冲突、离线模式、凭据回退、脱敏与计价声明；配置翻译也与命令分派混在一起。
这些行为需要独立契约验证，并保留已有 CLI 的模型工厂和凭据路径替换接缝。

## 决策

- `commands/configuration.py` 持有 CLI 参数翻译、配置文件发现、provider 默认值和
  config 命令。底层 `config.py` 仍拥有配置 Schema 与 CLI > 环境 > 文件的合并规则。
- `commands/models.py` 持有 ModelSelection、profile 选择、显式模型参数覆盖、凭据回退
  和 CredentialRedactingModel 包装。磁盘读写与模型传输仍由原 adapters 实现。
- `select_model()` 必须显式接收 ProviderFactory 与惰性的 credentials_path 回调；
  不从 CLI 反向导入宿主依赖，不捕获默认的真实模型工厂或用户目录路径。
- CLI 的 `_select_model()` 是宿主依赖绑定位置，向模块传入当前 build_provider_model
  和 default_credentials_path。既有测试与调用方的替换继续生效，离线模式不会因绑定
  过程提前查凭据路径。交互 UI 的输入、保存密钥与运行生命周期仍留在 CLI。
- `_resolve`、`_model_arguments` 等既有调用名通过函数对象别名保留；模型选择算法和
  配置规则均只保留一份实现。commands 继续遵守不反向依赖启动入口的检查规则。

## 替代方案

- 直接把函数移走并捕获真实模型工厂：会绕开 CLI 已有的替换接缝，增加意外访问真实
  模型或全局凭据的风险，不采用。
- 在调用模块之前求出凭据路径：会让离线模式执行原本不需要的路径发现，不采用。
- commands 回调 cli 或复制两份模型选择逻辑：造成反向依赖或行为漂移，不采用。
- 同时拆交互会话、运行组装与评测驱动：扩大安全敏感迁移范围，本轮不实施。

## 验证与结论边界

先添加直接模块契约，再迁移：覆盖显式离线选择、provider/profile 冲突、环境/工作区/
全局凭据优先级、模型输出脱敏、参数/环境不变、CLI endpoint/model 覆盖、无价格声明
时拒绝构建 provider、MLX 缺失路径及配置来源。全部使用临时目录和脚本/假模型。

迁移前后 29 个既有顶层函数/类经过语法树比较；仅规范化名称、文档字符串和两项显式
依赖注入后，原有函数体保持一致。此项静态比较不替代回归、安全或真实模型验收。
现有 CLI、交互和凭据回归继续验证宿主替换及脱敏链路。

CLI 降至 949 行。真实模型、真实凭据、评测队列与历史封存没有用于本轮验证；后续
评测须重新绑定当前源码身份，不修改旧协议指纹。按用户要求，本轮完成门禁后结束整理。
