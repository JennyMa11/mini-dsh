# ADR 0038：用可选批量读取验证反馈后的修复机会

- 日期：2026-11-07
- 状态：Accepted（离线开发；真实模型收益与费用准入未通过）
- 依据：用户目标“先解决交互可学习性，再继续比较 RL 算法”，以及 ADR0037 完整对照的负面机制结果。

## 问题与选择

工具示例对照中，10条获得修改后失败测试的轨迹，有7条之后没有真实采样机会，
其余3条没有成功提交新 Patch。仅追加示例尚未形成可复核的反馈修复路径。
下一阶段选择减少读取回合这一项假设，保留原任务、模型、Prompt及资源额度。

独立实验包增加可选 `read_files`：一次读取1–4个白名单文件，共享5000字符上限，
逐文件标记截断；控制组仍提供原四个工具，处理组额外提供批量读取，原 `read_file`
继续可用。额外 Schema 会增加 Prompt，因此估计的是“提供可选批量读取能力”的效果，
无法单独分离工具说明、工具选择空间和实际批处理的影响。

不修改核心 Loop、插件系统、权限或训练依赖。所有读取仍经过原 Tool Runtime，
控制面与容器内双重校验路径，任何路径不合法则整个请求失败。原始数据及 H1 结论冻结。

## 验证与判据

先验收同信息读取、共享输出上限、符号链接拒绝、无文件修改、真实 Loop 内失败测试后
再次修改，以及本地 tokenizer 的首轮渲染；脚本 Token 明确标记为合成数据，不进入训练。
真实对照固定8题×2seed×2组，共32条，不能用历史控制组或缩小分母替代。

H2 前瞻性机制判据为：成功批量读取发生在某次修改后的公开失败测试之前；该候选经
控制面独立检查确实未通过；之后成功提交新 Patch，最终候选独立通过。允许失败候选
是第k次 Patch，而非仅第一次；理由是研究任何有效反馈机会，避免漏记第二次修改后
才获得的反馈。此新口径仅用于尚未采样的 H2；不重算 H1 的预声明准入结果。

开发门槛保留成功率配对差为正、至少2个处理组独有成功配对、至少2个处理组家族
满足上述轨迹代理，资金独立准入。该门槛不等于显著性、因果推理证明或 RL 已有效。

## 费用与后续

累计上限50元不变。当前保守占用48.021元、可用1.979元，完整队列需预留2.88元，
所以当前只完成离线准备，不创建付费采样请求。可继续审计已结算账单；没有完整覆盖
证据不得释放预留，不清零或删除旧操作。是否获准执行以实时账本和完整证据为准。

若机制仍不通过，先分类“没有使用能力、反馈仍过晚、有机会但没有修改、修改仍错误”，
另定单变量假设。若通过，才规划新家族上的 success-only RL Pilot；GRPO/GSPO 比较
还须冻结共同初始化、轨迹归一化、训练剂量及全新留出评测，并另行证明资金可容纳。

替代方案是增加步数/Token、增加工具示例或换模型；它们分别改变资源或策略，当前暂缓。
回退只需保留默认 `single_read`，不影响旧工作流和旧 Prompt 对照入口。
