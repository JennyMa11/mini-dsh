# ADR 0026：Project Memory 的私有存储与维护边界

状态：Accepted（私有存储、来源与维护边界已实现并由契约及原生 OS 探针验证；阶段出关结论以 PR 4 独立报告为准，真实种子授权另行记录）。

Memory 的批准与提交属于操作者维护能力，模型最多提出摘要，只有 committed 知识进入 Context。计划通过显式私有存储授权绑定 SQLite 文件，放在 Agent 工作区之外；模型不持有数据库路径或 Store 对象，维护工具不进入模型工具集合，批准须在运行外进行。来源证据由可信外部索引解析，不能信任模型传入的 accepted/approved 标志。

仅把数据库放进 .minidsh 并拒绝普通文件工具不足以保护它：执行工作区代码的工具（包括固定可见验证）仍能绕过路径层策略。运行时接入存在进程能力时须使用实际 OS 隔离，并确保私有数据库没有挂载到 Agent 执行世界；仅允许路径工具的本地模式须另做能力检查。未知隔离能力失败关闭。该选择影响后续嵌入方式与部署，必须由真实副作用探针验证，不能用隐藏路径或 Prompt 替代。

持久化层保留完整记录条件更新及数据库事务；修改正文使证据与批准失效。状态完整性由 domain 校验，授权与来源核验由受控服务负责，数据库不被当作一份可自由读写的普通仓库文件。替代的工作区内存储、自动批准、终态回调写入和跨项目共享不采用。未经验证的提议仍可保留 proposed，不能自动提升为经验。

来源使用受信调用方登记的证据包 hash，绑定独立 sidecar、结束 Trace、判据和产物，或显式配置确认；实际文件通过固定根目录下的无链接读取核对。原始内容仅用于来源检查，不进入 Memory/Context。批准和首次提交复查证据，运行内检索也排除当前无法复核的候选，不反向修改历史记录。维护工具与隐藏检索工具分别注册在操作者和 Context 执行器中，模型工具集合仅含提议入口。

## 路径竞争修复的存储取舍（2026-10-30，已实现，阶段验收待归并）

直接把已检查的路径交给 sqlite3.connect，仍会重新解析路径。额外做一次检查不能消除检查与打开之间的竞争；目录描述符路径也可能被 SQLite 自身规范化。新增 C VFS 或依赖第三方 SQLite 包会扩大平台与供应链边界，本轮不采用。

保持 schema 1 与标准 SQLite 文件可读性，SQLite 只在内存连接上执行事务。磁盘读取通过已授权物理目录的描述符，最终文件以 O_NOFOLLOW 打开，并检查常规文件、链接数与身份；提交以同目录临时文件、fsync 和原子发布完成。目录被替换时不会跟随替换目录；末端符号链接不会被读取或写穿。取消与提交通知继续遵循原先的可读回结果契约。

同一物理根目录的协作 Store 通过目录描述符的进程级 advisory lock 串行化，避免整文件提交丢失并发更新，不创建隐式锁文件。普通读取不修改数据库字节。此实现仅在具备 POSIX 目录描述符、无链接打开、目录 advisory lock 和 SQLite serialize/deserialize 的 adapter 平台启用；缺少能力时拒绝，不回退到不安全路径打开。数据库容量上限 8 MiB，超限拒绝且不淘汰已有内容。此限制面向本轮小规模私有经验库，不扩张为通用数据库服务。

迁移不转换既有数据库；停止旧写入实例后，新 adapter 读取既有 SQLite 文件并保留记录。禁止与外部 SQLite 写入器或旧 adapter 同时维护该文件；有未结束 journal/WAL 的数据库拒绝接入，先在可信维护流程完成原事务。该目录锁仅协调本 adapter，不承诺约束恶意宿主程序；进程工具依然必须使用前述 OS 隔离。

读取回归使用 before_storage_read；发布回归使用 before_storage_publish，均是紧邻实际描述符 I/O 的固定故障注入点。原子发布完成后发现路径身份失效，以 memory_committed_notification_failed 返回；原授权目录内仍是完整新记录，调用方不能按异常推断回滚。实际两个进程的锁争用验证拒绝竞争写入且释放后无更新丢失。

参考：Python 3.12 标准库的 [SQLite serialize/deserialize](https://docs.python.org/3.12/library/sqlite3.html#sqlite3.Connection.serialize) 与 SQLite 官方的 [URI 参数边界](https://www.sqlite.org/uri.html)。不把 URI 的只读模式解释成路径无链接保证。
