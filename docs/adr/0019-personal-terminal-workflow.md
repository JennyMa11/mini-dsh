# ADR 0019：个人终端编码工作配置

- 状态：Accepted with limitations
- 日期：2026-10-03
- 补充：work 的默认 shell 策略已由 [ADR 0028](0028-work-default-shell.md) 取代。

## 背景

项目目标包括自己在终端改代码、跑测试、连续追问。已有 `chat` 默认只读，启用
编辑与测试需要多项权限参数；缺少项目说明预读和明确的验证状态，容易将模型回答
或工具执行完成误认为测试通过。评测接口本身不能替代可用的日常入口。

## 决策

增加 `work`，作为用户明确选择的工作区编辑配置。复用现有交互层、Agent Loop、
Tool Runtime、Permission、Context 和 Session，不实现第二套运行引擎。
默认提供定位、读取与修改工具；配置 `test_command` 后授权其执行程序，并只向模型
暴露固定 `test` 工具。通用 `shell` 默认不注册，需额外显式开启。配置的权限限制
优先于工作配置；`chat`、批处理与评测的默认权限保持原规则。

`workspace_instructions_enabled` 是显式运行依赖。Loop 使用注入的 ToolExecutor
读取根 `AGENTS.md` 与有限文件清单，每次调用计入工具预算并发布普通工具事件，
不在 Loop 中加入文件系统代码。读取结果作为命名事实进入历史。说明截断时停止；
不可读取时记录缺失事实，仍由工具权限阻止非法访问。嵌套说明通过提示要求模型读取，
此版本没有提供嵌套说明自动查找与强制验收。

工作配置使用 BudgetContext 1.1；最新用户任务、根说明、文件清单和手动测试反馈保留，
旧的命名状态在派生视图中被替代，原始历史不被修改。关键事实本身超出输入预算时
停止，不通过静默丢弃约束继续执行。
初始任务按第一条用户消息定位，避免在用户先连续执行 `/test` 时将旧测试反馈误当作
永久保留的初始任务；此变更不用于补认旧 Trace 的实验收益。

终端根据测试 Observation 的退出码与超时状态显示验证结果，显示测试输出与修改文件。
测试后继续写文件或运行可修改状态的命令，会使显示的验证状态失效。
该状态仅说明配置的测试命令是否成功，不是独立任务判据，也不能确认无其他副作用。

`/test` 是用户明确发起的固定工具调用，无需模型凭据，使用独立 Run ID 与工具 Trace，
其输出进入当前会话的后续 Context。它不消耗模型任务的 Loop 预算，仍受工具超时与
输出上限约束；历史在下一轮 Agent 任务保存时落盘，立即退出不创建独立可恢复会话。

`/key` 仅使用隐藏输入，凭据交给现有模型配置与脱敏链路，保存在进程内存。
若终端不能隐藏输入，拒绝回退到明文输入。没有额外持久化凭据。
此处仅内存的终端持久化策略已由用户要求和 [ADR 0021](0021-layered-credentials.md)
取代；隐藏输入与脱敏要求继续适用。

修复本地 runner 的取消清理：取消与超时复用终止进程的路径。POSIX 上杀死进程组，
Windows 上仅终止直接子进程；后者尚未提供 Job Object 级后代清理保证。

## 替代方案

- 改变所有命令默认权限：影响已有只读会话和冻结评测配置，选择单独入口。
- 自动猜测试命令：项目差异与执行权限不可由猜测授权，要求显式配置。
- 提供任意 shell 作为默认工具：固定命令已满足首轮日用目标，通用命令单独授权。
- 在 UI 直接读取仓库说明：绕过工具事件与运行预算，选择注入端口执行。

## 后果与验收边界

### 2026-10-03：讨论请求与空项目反馈修正

一次个人网页大纲请求返回了通用工程模板。原提示偏向编辑与验证，工作配置还默认
注入 `inspect/edit/test` 状态。改为优先匹配最新用户请求、复用已给定需求，说明
大纲与讨论应直接作答；简单个人网页从页面内容和视觉结构展开。工作配置默认关闭
Local-first 编辑计划，保留 `--local-first` 显式启用，冻结实验配置不作修改。
此修正是行为指引，没有增加关键词路由或强制判别任务类型的安全门禁。

`read_file` 1.1.0 将工作区内不存在文件报告为 `file_not_found`；返回该类型前再次
检查路径归属，缺失的仓库外目标与符号链接越界仍返回 `sandbox_violation`。
工作配置仅将根说明预读的 `file_not_found` 显示为正常缺省；原始失败 Observation
与事件继续保留。模型显式请求读取缺失文件、权限拒绝和其他错误仍显示失败。

该 Trace 中的用户输入与反馈中贴出的完整句子不同，缺字来源尚未确定。新增
`Request:` 输入回显用于核对，经过现有输出脱敏与终端控制字符过滤；没有宣称修复
终端输入法。离线测试验证完整中文文本传递、提示范围、可选说明状态与权限边界，
不以脚本模型响应证明真实模型的大纲质量已经改善。

离线终端测试覆盖读取说明、符号链接拒绝、显式只读、预读预算、说明截断、
文件修改、真实测试与追问、失败退出码、验证状态失效、手动测试反馈、内存 Key
与禁止明文回退。POSIX 取消测试观察后代进程未写出延迟副作用。

这些测试验证契约与执行路径，不衡量真实模型任务成功率。本次没有新增真实模型
实验；逐 Token 输出、可取消 HTTP transport、自动嵌套说明、超长说明分段读取
与大仓库日用验收仍待实现。已有本地模式安全限制继续适用。

### 2026-10-03：工具发现与本地执行环境说明

用户要求停止开发服务器的两次运行只有根说明和文件清单预读。模型请求没有
`shell`，但回答还错误声称不能访问用户本机。工作配置的默认提示现在包含实际
执行后端、通用命令工具是否注册及程序白名单；本地执行与容器执行分别说明。
用户自定义系统提示继续优先，不被工作配置覆盖。行动请求要求用已授权工具执行
并验证结果；提示不会新增权限或保证真实模型遵循。

增加 `/tools`，显示当前注册工具与权限；模型启动前使用无需凭据的本地注册预览，
明确说明 provider 扩展需启动后查看。入口不执行命令、不进行模型调用或改变权限。
缺少通用命令工具时给出启动参数说明。默认仍不授权 shell，也不自动授权 `kill`；
已有程序白名单不限制目标 PID，这个限制在使用文档中明确说明。

离线回归确认默认工具列表不含 shell、模型收到本地执行事实、显式授权后模型
选择的 shell 调用确实执行并将输出带回下一轮。该检查验证执行链路，不代表
真实模型停止服务器的任务成功率。

### 2026-10-03：终端回答风格

工作配置的默认提示明确终端助手身份，普通行动用一到三句报告结果、验证与具体
阻碍，减少装饰性标题、教程式多方案和重复工具日志。大纲、教学与详细解释按用户
要求展开；不在输出层裁剪正文或删除 Markdown，不更改用户自定义提示或冻结评测
提示。离线回归验证这些指引进入模型请求，不以脚本响应证明真实模型风格已改善。
