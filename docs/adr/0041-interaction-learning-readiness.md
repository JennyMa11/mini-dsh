# ADR 0041：以反馈覆盖和完整预算准备交互学习实验

- 日期：2026-11-07
- 状态：Accepted（离线协议准备；模型执行仍未准入）
- 依据：用户目标“先解决交互可学习性，再继续比较RL算法”、H1–H3结果和ADR0040审计。

## 决策与当前范围

当前阶段只完成已结算费用覆盖审计、新家族数据规格及可复算的训练/评测预算。
保留H1–H3综合门槛失败和旧开发数据开放的事实，不把反馈草稿组件通过当成模型收益，
不进行第四轮同开发集工具调整，不运行模型筛查、SFT、RL或算法效果比较。

新实验的设计见[交互学习准入协议](../trainable-agent-rl/interaction-learning-readiness.md)。
准备按家族隔离的8个候选家族/16题，先实现公开规格、两个跨模块缺陷和反馈覆盖矩阵，
再运行确定性离线验证。当前候选只有规格和case ID，没有任务实现或模型轨迹；后续
夹具与训练桥接实现必须另行记录阶段范围，不因本ADR自动启动。

在新任务上区分四件事：反馈覆盖、模型实际利用反馈、二值Reward的组内变化，以及
更新后独立留出任务的改善。最后一项才构成学习收益证据。新数据准入不以旧工具
处理组是否获胜替代，也不对旧失败重新打分。

## 最小侵入与实际缺口

保持核心Loop和插件不变。MiniTask及其现有工具可复用，但现有minirepo_rollout只返回
开发结果dict；train_v2使用旧Task/Rollout对象，不能直接传入MiniTask启动训练。
后续需要独立typed训练结果及原始Token/验证记录桥接、新split/criterion绑定、固定组
调度及训练恢复；不通过改旧开发result字段或重新编码模型输出来兼容。

费用仍由唯一活动CalibratedBudget管理。闭合账期的整个工作空间费用只能在完整调用
覆盖审计后作为所识别子集的保守上界；不释放历史、未知或管理费用。
完整readiness、训练、结束保存及配对评测须在首次付费调用前一起预留。

## 替代方案和后续条件

继续增大读取数量或输出上限，暂不采用：H1–H3已未显示稳定整体收益。
直接比较GRPO/GSPO，暂不采用：尚无小仓库学习证据，且现有两实现还具有Token/轨迹
归一化差异，不能把全部效果归因于ratio/clipping。
使用当前公开反馈草稿直接训练，暂不采用：它仍是原四个开发家族，不是独立train/test。

原累计50元上限保留。新方案若不能完整容纳，先完成离线数据与桥接，再提交具体预算
调整供用户选择，不以部分可支付为理由先采样，也不删评测、缩短任务或借用已打开test
凑出可执行队列。目标保持active，当前没有学习收益或算法比较完成证据。
