# ADR 0016: 本机轻量公开修复评测

状态：Accepted

## 背景

SWE-bench Pro V2 的多 GB 镜像、amd64 仿真与复杂工具链不适合用户的本机。
用户要求替换为 Python 与 JavaScript 的轻量公开修复题，继续使用 DeepSeek，
单任务至多 1 CPU、1 GB 内存，整轮名义预算 20–30 万 Token。

## 决策

- 采用 HumanEvalPack 的 HumanEvalFix-docs 子集：6 个 Python、6 个 JavaScript
  独立修复任务。按规格与上游错误类型选题，在模型运行前锁定版本、记录和预算。
- 单任务 20,000 Token、16 步、32 个工具调用、180 秒；整轮 240,000 Token。
  仅使用标准库/语言内建能力，无第三方包安装或大型仓库构建。
- 固定本机原生架构与两个小型官方语言镜像的 digest，容器最多 1 CPU、1 GB、
  128 个进程，断网、无挂载、无 Secret。资源参数属于通用容器 adapter。
- Agent 通过 Tool Runtime 的 argv 工具读取、修改函数源文件并运行公开示例。
  参考解和完整测试仅用于新的独立验证容器，永不暴露给模型工具。
- 使用未修改的上游测试输入。JavaScript 的 `console.assert` 必须产生可判定失败，
  不能因为 Node 默认只打印失败而把退出码 0 当作成功。
- 全部参考解通过、全部原始缺陷实现失败后才调用模型。成功率、失败消耗与未运行题
  使用完整分母；Provider 用量未知时停止后续任务，不计算费用。

## 替代方案与范围

单纯 HumanEval/MBPP 生成题更轻，但没有已有缺陷实现，较少覆盖修改与验证循环。
缩减 SWE-bench Pro 题数仍保留重镜像和仿真问题，故更换数据集而不是删除失败题。

该子集评估函数修复与工具循环，不代表大型仓库、多文件或长上下文能力。
已有本地 Harness 攻击、恢复和 Context 测试应单独报告，不能混入公开题成功率。
这是自定义受限协议，不声称官方全量 HumanEvalFix 成绩。

## 例外、迁移与复现

独立函数任务没有初始仓库提交，用固定上游提交、完整记录 SHA-256 和初始文件
SHA-256 定义输入，不虚构 Git 提交。镜像、架构、预算、工具和 Harness 源码均留档。
独立准备路径沿用 [ADR 0015](0015-public-container-benchmark.md) 的受信任编排例外
与管理员工具迁移计划；核心 Loop 不增加数据集依赖或模型直接 IO。
源码下载优先使用国内公开代理并核验上游 Git blob 与 SHA-256，镜像优先国内代理
并核验官方平台 digest。代理不接触 DeepSeek 凭据，不改变容器的断网边界。
