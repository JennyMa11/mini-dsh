# ADR 0011：GUI 协作设置与内存凭证

状态：Accepted

## 背景

ADR 0008 的 GUI 只展示启动配置。新增协作能力后，用户需要直接在页面输入 API Key、启用 Multi-Agent 并设置并发，同时保持既有权限边界。

## 决策

- GUI 展示层通过显式设置工厂重建 Runtime，保持核心 Loop 和单工作区基线不变。
- 设置只允许 API Key、协作开关、累计子 Agent 上限、并发上限。模型、工作区、权限和全局预算沿用启动配置，未知字段拒绝。
- 进行中的任务拒绝设置变更。候选 Runtime 创建成功后才替换，保留对话；构建失败保留原配置。
- Key 经本地受认证的 HTTP 接口提交，使用 SecretStr 保存在服务内存。不回显、不写入配置或浏览器存储，关闭服务后清除引用。请求验证错误返回固定安全消息。
- 凭证通过局部环境映射传给主模型与子模型工厂，不修改进程环境变量。模型输出和错误在进入 Loop 前移除已知凭证，避免意外回显进入后续 Prompt、Session 或 Trace。
- 子任务卡片按独立运行 ID 展示状态和结果；子 Agent 继续受 ADR 0010 的只读工具与团队预算约束。

## 替代方案

将 Key 写入配置文件或浏览器存储便于跨重启使用，但增加凭证持久化风险，因此不采用。通过修改全局环境变量重建模型会影响并发请求，也不采用。

## 后果与迁移

原有环境变量和 CLI 启动方式继续有效。关闭服务后页面输入的 Key 不保留；现有页面需重新启动服务并使用新地址。此决策扩展 ADR 0008 的只读设置展示，不改变启动授权范围，也不提供模型切换或插件市场。
