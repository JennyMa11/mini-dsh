# ADR 0040：用离线缺陷探针审计公开反馈覆盖

- 日期：2026-11-07
- 状态：Accepted（离线审计；不启动新模型队列）
- 依据：用户目标及H3“公开测试通过、独立验证失败”的明确规格反例。

## 决策

保持原8题、公开/私有判据、H1–H3评分及门槛冻结。在独立实验包增加离线审计入口，
对同一候选分别执行原公开测试和私有测试；使用新容器，结果只写新的派生目录。
范围包括reference、原始bug、常数错误解、逐个恢复的原始缺陷，以及从公开规格构造的
四类语义探针：库存不足、相同时间事件、None与缺失、税额向上取整。

目的不是把旧任务补成通过，而是检查反馈是否足以识别有代表性的部分修复。
已知原始缺陷全部被公开测试捕获，也不代表全部规格语义都覆盖；两种覆盖分别报告。
策略/语法拒绝、超时及未执行不能冒充功能探针被检出，需单列检查分母。

## 实现与结论边界

新增纯探针契约/构造器及顺序Docker审计器，不改AgentLoop、工具、模型、Reward或原任务。
隐藏测试、参考解和语义标签仍只在控制面；没有模型参与，也不上传候选或判据。
固定探针在执行前完整枚举，保留全部分母和公开/私有sidecar及hash。

报告区分执行完成、reference正确性和反馈覆盖；发现覆盖缺口是有效审计结果，不把
“审计运行成功”写为“任务反馈已充分”。原财务账本前后hash必须一致。

若未来生成新任务，应先冻结规格子目标与语义mutation，再对公开反馈做门禁；新任务
及新判据必须新版本、按家族隔离，不覆盖旧模型工作区或对旧结果补认成功。
本决策不授权新任务模型筛查、SFT/RL训练或算法比较；完整资金和机制门槛仍须另行证明。

离线审计后的当前范围补充：原始缺陷16/16被公开测试检出，但8个语义实例（4种唯一
程序探针）均公开通过、私有失败。因此制作显式新ID的development反馈夹具草稿v2，
只补充公开规格导出的反馈例子，不更改旧Task对象、源码、私有checker或任何旧结果。
对草稿重复相同48探针审计；这是有限反馈覆盖修复，不是模型收益或新训练/留出数据。
