# ADR 0031：项目记忆采用渐进读取与提议式整理

状态：Accepted with limitations（P2渐进读取已验收；P3结构化历史/P4整理仍按各阶段独立契约实施，未完成）。日期：2026-11-11。

P0/P1原始设计和P2验收时的ADR bytes随各自冻结记录保留；当前状态更新依据[P2报告](../results/memory-v2-p2-2026-11-11.md)，不回填原证据。

## 背景

当前 Memory 有完整证据、批准和私有存储链，但模型只能提议，检索主要依赖工具路径/错误，缺少主题发现和主动读取。开源框架提供自动整理或完整服务栈，但直接引入会把模型调用、权限、预算和持久化扩展到另一套执行机制。原计划明确不做自动总结，需要记录新范围而不能静默实施。

## 决策

保留私有 SQLite 与 proposed → validated → approved → committed 状态链，以可重建的运行内索引、主动搜索和按引用读取扩展现有 Memory 模块。区分发现资格与正文适用性；索引只暴露已经批准的 topic/范围元数据。P2 保持 schema 1，新增模式显式启用，v1 不变；后续整理仅在运行外手动触发，产生提议，操作者继续批准。

## 替代方案

1. 整体接入 ReMe、LangMem 或 Hindsight：能力丰富，但会引入额外模型/存储/后台执行语义，不符合本阶段轻量约束。
2. 把 Markdown 文件直接作为 Memory 事实源：便于编辑，但宿主编辑或 Actor 写入可能绕过现有批准绑定，需重新定义安全和迁移；当前不采用。
3. 只扩充 v1 路径规则：代价较低，仍无法让模型在未访问文件时发现经验主题，不能满足本轮目标。

## 后果与迁移

需要自行实现词法排序、卡片/正文预算、来源和修订复查；暂不解决同义搜索或跨主题语义矛盾。P2 不转换数据库，回退时移除新配置并切回 deterministic_v1；旧批准仍有效，索引可丢弃。P3 的持久化变更另立迁移契约。不会自动批准、跨项目共享、增加 observer Agent 或后台调度。

本 ADR 只规划新的读取入口；ADR 0026 对私有目录、OS 隔离、证据正文不可见和运行外维护的规定继续生效。详细设计和 case 见 [Memory v2](../memory-v2-design.md)、[验收设计](../memory-v2-acceptance.md)，取舍依据见 [P0 源码调研](../research/memory-frameworks-2026-11-11.md)。
