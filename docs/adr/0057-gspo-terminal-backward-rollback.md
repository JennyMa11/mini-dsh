# ADR 0057：GSPO 已终止反传任务的检查点回滚

- 日期：2026-11-09
- 状态：Accepted（原研究的受控故障恢复，不改变算法、数据或终点）

ADR0056 的 run-01 在第31组（slot30）反向传播结果查询时发生 EventPollingError。
原任务 owned/ENDED，30组、19次更新与全部对应检查点已确认；已采样124条。
第31组 journal=backward_submitted、无forward完整回执、无optim提交或新检查点，
SDK在反传查询失败时将梯度累加范围标未知，不能继续使用该Actor，不能重放该请求。

允许一次新目录恢复：冻结原失败、原pending与原源码，核验最后确认的optimizer+sampler
均READY，下载其实际权重/优化器。新任务必须通过restore_optimizer加载该完整检查点，
保存新检查点，逐张量/标量核对LoRA及完整非空优化器state与param_groups完全相等。
禁止fresh seed代替已训练优化器；加载或核验失败就停止，不递归恢复。

新run-02继承原30组已确认回执及124条已采样轨迹，原始字节与输入hash不变；
只在干净的新Actor上重建第31组事务，之后继续原40组/352行队列，不重新采样或挑题。
新事务是从确认检查点重算的独立事务，绝不续用旧Actor的未知梯度。原未知调用保留
保守预留，仅以其owned/ENDED、未提交optim、明确scope/hash的冻结证据隔离阻断；
任何其他未知调用仍阻断。恢复目录、恢复调用与独立数值核验均持久化且仅执行一次。

恢复不改变原比较：Base初始零LoRA与GSPO固定40组终点，完整64验证、128测试。
报告明确跨Actor恢复及原失败，不能称全程无故障。未能证明恢复一致则保留完整分母，
不把30组部分结果冒充GRPO同规模的GSPO结论。

已保存的训练后Adam检查点约196MB，恢复下载单独固定256MiB流式上界并验证TLS、
owned与URI关联；不修改原初始权重下载器128MiB上界，不提取归档路径，optimizer使用weights_only加载。

run-02 的第一个restore和检查点保存已确认，下载在异步上传READY前提前退出；未提交任何新
反传/optim。补做只读下载证明完整权重差0、Adam状态及param_groups全等。修订恢复IO
为8次/2秒有界READY等待；保存修订前plan/source并绑定新plan。仅在此已确认且无新
训练的边界允许第二次SDK连接（总计不超过原2次恢复额度），再导出并复核实际状态。
这不是对未知反传或optim重试，若出现新的未知请求仍立即停且不递归恢复。

训练后约196MB检查点上传连续两次超过原16秒窗口；两次restore及state/sampler保存
均已确认，未提交任何新的反传或optim，无新增未知事务。第一份保存归档已证明完整Adam
和权重全等。此为已确认保存边界的IO就绪问题，不是优化器恢复失败。将此类大归档
READY查询固定60次×5秒（最多5分钟），一次新目录run-03继承同一原124条轨迹/30组/19更新，
作为最后一次已确认边界连接；原2次只读等待停点与两代源码快照均保留。
不得对未知反传/optim按此逻辑扩张恢复。run-03若新故障不能按原完整回执恢复，则停止。
