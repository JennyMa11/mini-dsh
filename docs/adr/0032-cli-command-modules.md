# ADR 0032：CLI 参数、离线查看命令与 work 配置分离

- 状态：Accepted
- 日期：2026-11-05

## 背景

CLI 入口同时持有命令声明、模型和凭据选择、运行接线、评测驱动、报告渲染与 work
默认配置，共 1816 行。修改参数语法或报告展示需要在运行与凭据代码之间定位，增加了
维护成本。用户在第一轮结构检查后要求继续整理，沿用先稳定分层和检查的范围。

## 决策

新增 Presentation 层的 `commands/` 包，按实际职责拆分：

- `arguments.py`：唯一的命令语法与参数默认值；`build_parser()` 返回 argparse parser。
- `reports.py`：读取已保存的报告/Trace，渲染、比较和计分，不启动 Agent。
- `work.py`：`apply_work_preset()` 按配置来源补默认值，保持权限与提示词内容。
- `__init__.py`：仅说明职责，不聚合导入命令实现。

`cli.py` 保留 main、默认 work 入口选择、错误到退出码的转换、模型/凭据选择、运行接线
和真实评测驱动。本轮不迁移这些有共享状态和安全语义的职责。

现有调用方使用的 `_build_parser`、`_work_config` 在 cli 中作为函数对象别名保留，不
复制实现或增加透传函数。`main`、`task_options`、console script 与模块入口保持原位置。

结构检查将 commands 归入 Presentation，并增加包括包入口在内的单向规则：commands
不能导入 cli、__main__ 或 work_profile。生产内层也不能导入 commands。允许列表的
其他层级关系不变，不因此次移动放宽 Application、Domain 或 Ports 的依赖。

## 替代方案

- 把每个子命令都拆成单独文件：当前不足以带来独立职责，反而会重复模型和配置接线。
- 一起迁移所有模型/凭据/运行组装：同时改变大量调用和测试接缝，超出本次范围。
- commands 回调 cli 中的公共帮助函数：会保留反向依赖，难以形成单向结构。
- 复制参数定义或 work 默认值：容易产生多入口漂移，拒绝。

## 验证与限制

先补参数、权限撤销、空工具集、报告错误与 Markdown 文件输出契约，再移动实现。
原有 CLI、终端工作流与 Trace 回归继续使用。迁移前后 41 个顶层函数/类经过语法树
比较，仅规范化函数名与文档字符串后，函数体和参数签名相同；这项静态比较不替代测试。

不改动历史评测数据、冻结源码归档或运行记录。新源码自然改变后续源码指纹；不能把
旧冻结实验的断点协议改写为新源码协议，后续真实评测仍须按原入口重新绑定源码身份。
CLI 仍有 1289 行，评测驱动与模型接线是后续独立维护项。本次不调用真实模型服务或
启动新的真实评测队列。
