# ADR 0049：已计入整段账单的补充覆盖与资金基线校正

日期：2026-11-07；状态：Accepted（需独立覆盖复核后才能应用）。

固定学习队列已在确认边界等待资金。旧Screening及两次Smoke的968次采样仍保留估价，
但其时段包含在已按整个JennyMa工作空间计入的00–04时账单上界9.72元中。选择复核
完整追加顺序、原始Token/Trace、资源归属与闭合账期；通过后只补充已有总额的覆盖。
不释放14.79元历史余额，不调整112项非采样预留，不引入尚未结算的新实验账单。

复用CostStore.reconcile增加一条增量金额为0的审计记录，引用已计价的4个provider
bill ID及原9.72元覆盖记录。原有bill金额/覆盖记录保留，968项原估价只去重一次。
增量0不表示这些请求免费，也不能对同一provider账单重复计入费用或重复释放同一操作。
这是当前操作估价的补充覆盖，不是ADR0047中的历史余额结转，不创建新accounting epoch。

因为释放发生在研究开始前的旧费用，必须同步校正研究start_committed，精确保留本轮
新增费用差值。只在awaiting_settlement、无pending、所有运行/更新回执一致时处理。
按正常入口同序获取财务租约和controller租约，先将控制状态设为不可恢复的财务事务
围栏stopped，再执行已审核reconcile，最后发布只调整资金基线/控制历史的原等待状态。
中途崩溃时围栏阻止SDK恢复；专门的幂等恢复程序核对before/after hash后才能解围。
原始Trace、判据、policy、队列、计数及已确认checkpoint不得改动。

替代方案是等待当前小时账单、重做历史epoch或放松阶段预算。前者仍可采用；后两者
无此需求且增加风险。应用前需对重复释放、输入变化、pending、围栏和各崩溃点进行
契约测试及第二路径复核。若任一证据不足，保持等待，不降低门槛或提高50元上限。
