# ADR 0025：可见验证位于完成检查链末尾

状态：Accepted with limitations；PR 3 出关仍以阶段报告为准。

真实回归复现了“可见验证通过，后序完成回调经受控工具改坏文件并 allow，Loop 仍 finished”。可见验证要求检查最后的候选修改，因此组合器在已有完成策略之后注册 Verification；每次提议通过只读顺序查询确认自己是最后一个 before_finish 检查，不满足时在工具执行前返回 verification_order_invalid。观察回调不影响此判断。HookRegistry 的原注册顺序、首拒绝短路和核心 Loop 均不改变。

完成决策回调须在组装前注册；要增加后序完成策略，应关闭并重新组装 Runtime，使 Verification 再次位于末尾。这项限制影响插件集成方式，故显式记录。自动重排会破坏 PR 1 的顺序契约；一次提议内反复补验会改变单次固定检查和最多三次完成检查的边界，均不采用。普通模型“先测试通过、随后修改、再次完成”始终重新检查。

保证适用于经 Tool Runtime 的协作式扩展。Python 扩展不能凭此被视为 OS 隔离；直接绕过端口进行 I/O、或在终态通知中产生副作用，仍违反项目约束。独立产物验收继续与可见验证分开。
