# ADR 0036：小仓库交互修复实验

- 日期：2026-11-07
- 状态：Accepted（阶段范围；收益需独立验收）
- 授权：用户设定目标“按照上述的规划继续”。

沿用 ADR0034 的独立实验包，不改核心 Agent Loop。本阶段制作4个开发家族×2变体
共8题，提供 read_file/search_repo/apply_patch/run_tests 四类 Docker 内工具，允许
受控项目模块 import 与预声明多文件修改。私有验证器、参考实现、mutation 和标签
不进入模型工作区。全部副作用经 Tool Runtime、Permission 与 networkless Docker。

第一阶段为同初始策略的一次提交/多轮修复对照：8题×2 seed×2模式=32条。
一次提交在第一个成功的多文件 Patch 后锁定候选，由控制器生成无Token消费的
终止响应（单独记录，不伪装真实模型生成）；无效Patch不算成功提交。多轮模式
可继续利用公开测试反馈修改。此对照同时改变再次修改和后续反馈利用机会，
不能单独归因于RL。两组除模式外保持相同预算、初始状态与采样设置。

沿用共享累计50元账本，不释放历史预留，不按新阶段清零。当前44.199元、剩余
5.801元；先离线任务/安全门禁，再为完整32条预留资金。阶段上限与后续训练
准入须写入冻结协议，若无法容纳训练及完整评测就停止，不自动扩额。

开发集只用来判定交互任务可行性，不能成为后续held-out test。训练/验证/测试
后续按缺陷家族独立划分，原已打开测试保持历史。最终正确性、预算终态、工具
错误、轨迹机制及统计不确定性分别报告。停用新实验入口即可退出。
