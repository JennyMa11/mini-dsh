# ADR 0010：可选的单进程 Sub Agent 协作

- 状态：Accepted

## 背景

仓库首版边界限定为单 Agent，用户现明确要求 Multi-Agent / Sub Agent 协作。已有插件组装允许替换端口，可以在不改变单 Agent Loop 的情况下加入调度层。该 ADR 记录对首版限制的显式扩展。

## 决策

新增可选的协作组装入口与 `delegate_sub_agents` 工具。主 Agent 按批次委派任务，Sub Agent 使用独立模型实例、Context、运行 ID 与 Session；返回结构化结果供主 Agent 汇总。支持角色提示词、并发上限与累计委派次数上限。CLI 与命名配置可启用协作；默认继续使用原单 Agent Runtime。

协作仍为单进程、单工作区；Sub Agent 首版只读，可调用读取、检索和只读 Git 工具。实现修改由主 Agent 完成，避免多写者竞争与权限扩大。子 Agent 不获得委派工具，不支持递归生成、分布式协作或自动合并。

在扩展层包装 Model、ToolExecutor、Event 与 Session：全团队共享步数、Token、工具调用和墙钟预算；每个子 Agent 还有自己的四层预算。已报告的 Token 和成本归入主运行摘要，子事件携带主运行 ID，启动与完成关系显式记录。无法预知的模型响应 Token 仍可能使一次响应越过 Token 上限，之后不再启动调用，沿用既有单 Agent 的计费语义。

所有委派先经 ToolRuntime Schema 与 `agent.delegate` 权限判断。超时与取消须等待子任务退出，防止后台遗留。协作组件遵循显式依赖注入，不引入全局服务定位器。

## 替代方案

- 把并行协作写入 AgentLoop：增加核心状态机复杂度，也破坏单 Agent 基线。
- 子 Agent 共用一个有状态模型或上下文：造成会话串扰，脚本模型消费顺序不可复现。
- 共享工作区并行写入：需要工作区隔离、冲突处理和合并契约，首版暂不引入。
- 每个子 Agent 只使用独立预算：可以通过委派绕过主运行预算，因此采用共享总预算。

## 后果与迁移

单 Agent API 保持默认兼容。协作通过新的显式组装入口启用，Sub Agent 使用当前模型服务的独立 adapter，也可由 Python 工厂指定其他模型。后续写入型协作应先定义隔离工作区、文件归属和合并判据，新增 ADR 后实现。
