# ADR 0044：先离线验收固定队列与恢复，再开放真实执行

- 日期：2026-11-07
- 状态：Accepted（离线调度与准入阶段）

## 当前范围

在已完成数据/桥接之上新增冻结的80条readiness、训练及配对test队列，完整资金
准入、单写者状态机及确认checkpoint后的恢复。先用注入式contract fixture验收，
不调用真实ServiceClient、采样、训练或修改活动账本，不开启算法效果比较。
核心Loop、旧运行器、判据和Reward保持不变。

初始化、采样、更新、保存均先持久化pending；只有完整receipt/独立轨迹可被提升为
已完成。缺少确认时停止，不自动重新提交；确认更新后必须保存带optimizer的state
和对应sampler快照。恢复不重放梯度，未运行case留在原清单。

## Checkpoint及预算修订

为支持每个有效组之后安全恢复，改为初始state及每次有效更新均保存state；最终
评测复用最后已确认sampler，不重复导出final sampler。最多9次state、9次sampler
保存，8次optim及一次client创建的原管理预留规则共1.890元。
完整80条采样7.200、8组padded训练10.712、管理1.890、额外准备/恢复额度0.500，
合计保守分配**20.302元**。它是预算规则上界，不是已证实提供商管理收费。
此前19.702元草案保留；当前上限仍50，可用7.333元，故真实执行未准入。

准备/恢复0.500元是硬额度，不保证所有尚未实测的新准备都能完成；不足时整个
研究队列保持未运行，另行修订协议，不借用评测预留。额外恢复最多两次，其client
创建预留从该额度扣除。资金和真实provider身份/数值验收均不得由fixture结果替代。

## 验收边界

contract fixture只检验控制状态、队列、同snapshot分组、完整分母及拒绝重放。
fixture的provider型数据对象是人为构造的单元输入，整个执行标记contract_fixture，
不冒充真实模型轨迹、参数更新、SDK恢复或成功率收益。实际SDK适配仍须后续接入
并实测；本阶段不因模拟控制闭环通过而宣布交互可学习性或算法比较完成。
