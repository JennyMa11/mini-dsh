# Harness follow-up v2：先固定设计，再执行

本轮响应“提高 Token Budget，完成旧轮未完成的机制验证，并扩大真实模型回归”。
v1 的 24 行与历史 10 次真实模型回归保持原样；v2 不续写、补认或重跑其中的失败行。
当前工作区已有改动，以完整源码、测试、锁文件、协议快照及 SHA-256 固定本次版本，
不要求提交或覆盖用户现有修改。

## 分析与假设

v1 单次 8000 Token，Full History 前两次 API 请求即消耗约 17000 Token；
输出 A 单次请求约 11000 Token。旧预算没有为完整观察、修改、smoke、结束预留空间。
旧 public-lite 最大记录消耗为 24338 Token。它们只用于本轮预算规划，不进入新轮成绩。

- 回归：原有 12 道公开题，各 3 次，共 36 行；每次 32000 Token。
- 机制：Context、Output、Recovery 各 4 道题（Python/JS 各 2），各 3 次 A/B，共 72 行；
  每次 64000 Token。整轮共 108 行，名义总额度 5760000，停止线 6000000 Token。
- 16 步、32 工具调用、180 秒保持不变。API 响应后可能在途超量，全部记账并停止后续调用。
- 固定 deepseek-flash、temperature=0、thinking=false、最大输出 1024、模型/工具自动重试为 0。
  记录服务实际返回的 model/fingerprint；不可变权重快照与 seed 未提供时保持未知。
- 每次单 Agent、顺序执行；Linux 原生架构、1 CPU、1 GiB、128 PIDs、断网、无宿主挂载及凭据。

本轮仍是已知公开函数修复题上的小样本；108 行不等于 108 个独立任务。
重复次数不是功效分析。每组仅四个任务，不宣称通用排名或显著性。

## 冻结的主要判据

运行前固定 [protocol.json](../benchmarks/harness_study/v2/protocol.json)。不得根据成绩调题、
调整阈值、选择性补跑。每次使用新的候选容器，在全新验证容器执行原始隐藏测试；
参考解、判据与评分器不进入 Agent 工作区。先验证全部 gold-pass / buggy-fail。

| 组 | 唯一变化 | 主要比较 | 机制检查 |
|---|---|---|---|
| 回归 | 无 A/B | 每题三次独立验证通过、完整目标与预算合规 | 不注入合成长历史、日志或故障 |
| Context | full / budget | 配对总 Token 差、输入 Token 差，修复与约束分别报告 | 压缩实际触发、关键事实保留、完整工具轮次 |
| Output | 131072 / 8192 字符 | 配对总 Token 差、完整目标通过（修复＋最终诊断） | 头/尾诊断保留、B 实际截断 |
| Recovery | 错误恢复关闭 / 开启 | 五次工具内恢复与最终修复分别报告 | 三次不同参数等价文件错误、B 恢复提示 |

Context 的 4096 选择预算、两侧共享的 8192 输入估算准入、日志大小及诊断位置、
五次工具内有效动作＋smoke＋独立测试的恢复判据均沿用 v1。
两侧除指定 RuntimeOptions 字段外相同；每题/每轮交替 AB/BA，总数平衡。
机制刺激由固定零 API Token 响应提出，但实际工具经 Runtime 执行；这些步骤/工具照常计数。
本轮研究受控故障下的恢复，不估计自然故障发生率。

## 指标、缺失与不确定性

分别报告候选修复、完整目标、预算/关键约束合规、终态和窗口恢复，不能互相替代。
未运行行保留在 108 行完整队列；未知用量停止整轮，已知消耗仍保留，不记作零消耗。
保留逐任务、逐重复与 A/B 结果，同时报告完整配对数、触发配对数及两侧均合规配对数。
无效或未触发的配对仍在完整队列，不能删掉后宣称收益；预算截断需单独说明。

总 Token 配对差 B-A 先在每题内部平均三次重复，再在任务间等权平均。
对四个任务做 2000 次 cluster bootstrap（seed=20261028），给出描述性 95% 区间，
不把重复样本当独立题目；区间不能覆盖选题偏差、模型别名变化或所有服务随机性。
成功结果报告两侧计数和不一致配对，不用零宽经验区间宣称真实成功率为 100%。
只统计 Token，不计算货币费用。失败模型调用的已知 usage 计入总量，未知 usage 单列。
每行核对 Trace 调用用量和终态总量，并拆分模型、工具与 Harness 墙钟残差；
Harness 残差不等同 CPU 时间。独立验证耗时与 Loop 延迟分开，不混入 Harness 开销。

## 执行与证据

先运行质量门禁，再执行 check。check 包括 20 个功能 case、实际内核隔离探针、
12 对参考验证、所有刺激门禁、单变量校验，以及两个合成小任务的完整离线演练。
演练使用脚本模型验证导出、sidecar、恢复检查点与汇总链路，消耗零 API Token。
所有门禁和源码 hash 检查通过后，run 才读取 .env.deepseek；不导出凭据到容器。

```sh
uv run python -m minidsh.benchmark.followup check --output benchmark-results/harness-study/v2-new
uv run python -m minidsh.benchmark.followup run --output benchmark-results/harness-study/v2-new --credentials-file .env.deepseek
```

每行原始 Trace、候选、独立验证收据、run_id 绑定 sidecar、分层指标及源码快照保留在忽略目录。
结果生成后另存 docs/results 派生报告并记录来源 hash，不改动 v1 报告。
修复前后版本不能混算；新的实验结果产生前，不提前更新简历中的实测次数或收益。

## 2026-10-28 执行结论

[可再生成结果与来源 hash](results/harness-followup-v2-2026-10-28.md)及其 JSON 已归档。
原始数据目录为 `benchmark-results/harness-study/v2-20261028-run1`；首次 check 的离线演练
发现审计未容忍毫秒字段的三位小数舍入，在零 API 调用时修正并增加回归检查，随后新目录
重新执行全部门禁。正式采样中源码、测试和协议 hash 未变化，没有选择性重跑。

- 108/108 行执行，559 次真实 API 调用，总消耗 2454087 Token，未知用量 0。
- 普通回归 36/36 正常结束、修复通过并满足已声明约束；范围为 12 道公开函数题。
- Context：总 Token 564913 → 339765（-39.86%），输入 -40.46%；修复两侧均 12/12，
  正常结束 9/12 → 12/12。A 的三次失败触及两侧共有的 8192 输入估算准入，
  不是供应商的上下文上限。结论限于本轮历史刺激和准入设置。
- Output：总 Token 535838 → 224691（-58.07%），修复两侧均 12/12，
  完整“修复＋最终诊断”7/12 → 12/12。A 的五次准入失败全部保留，
  不能只挑双方 finished 的运行报告节省，也不能把不等价轨迹说成纯文本压缩收益。
- Recovery：窗口内恢复 6/12 → 12/12，最终修复 11/12 → 12/12。
  关闭侧一次反复读取缺失文件，同时触及 16 步及 64000 Token，实耗 66560，
  超额 2560 全部计入。总 Token 均值差的任务聚类区间跨零，且差值受该长尾失败影响，
  不宣称恢复机制普遍节省 Token；窗口改善也是四个选定任务的观察结果。
- 全部运行：独立修复通过 107/108，完整目标通过 102/108，正常结束 99/108。
  “完整目标且满足已声明约束”仍包含三次产物正确但随后准入失败的 Context A，
  所以不能把该 102/108 改称正常完成率。

108 份 Trace 回放、终态用量和 API 次数核对一致；2089 个保存文件中实际配置密钥的精确
匹配为 0。该扫描不代表所有 Secret 的通用零泄漏证明。失败模型用量的已知/未知路径由
离线故障注入验收；本轮八个 model_call_failed 为已知零用量的调用前准入拒绝，不能说成
本轮观察到了八次收费 API 失败。559 次实际 API 中 558 次含缓存输入；脚本响应和准入
拒绝不加入 Provider 缓存命中率分母。

所有配对、失败、超额和原始报告保留。四任务聚类 bootstrap 描述选定任务内不确定性，
不证明跨仓库或大型工程通用收益。历史 1010 次离线执行仍为历史记录，不冒充本版本重测。
