真实运行源码hash全程一致，全部失败与资源终止保留，没有训练或新test。

各3对。八项组满足≥2个独有成功配对及≥2反馈家族，但成功率配对差不为正，综合门槛
仍失败。不得选择性保留已通过条件，或因这次结果降低阈值进入RL。

仅4家族、8题、每题两次，且同开发集已进行多轮假设探索；不是16道独立题，也没有
训练seed重复。不能证明两上限等效，也不能把本轮四项4/16对比H2的3/16归为模型升级。
后续泛化评估必须使用独立任务，不把当前开发数据包装为未见test。

八项组工具调用少0.8125次，约7.18%，总Token仅少276（0.053%），基本持平。
估价按每RPC每类别0.001元向上取整，少调用会减少估价余量，不代表实际费用一定降低；
不能据0.012元差宣称经济收益。端到端延迟受网络、服务及控制面影响，没有稳定加速证据。

## 反馈路径：容量已有直接证据，收益仍不确定

八项组两条通过完整代理的轨迹：

- `paired-01_006_batch_read_eight`，`mini_inventory_1`：第7步首次Patch，第8步公开测试
  失败，第10步新Patch；首次候选运行后私有复评失败，最终候选独立通过。
- `paired-01_014_batch_read_eight`，`mini_windows_1`：第8步首次Patch，第9步公开测试
  失败，第11步新Patch；首次候选私有复评失败，最终独立通过。

两条均在失败反馈前实际成功使用批量读取，符合预声明顺序；覆盖inventory/windows。
四项组`paired-01_028_batch_read`在billing家族也有同类路径。其余多Patch成功没有所需
公开失败反馈证据，不补认机制。私有复评只在结束后进行，未向模型泄漏判据或参考解。

这证明当前未训练策略在该工具与额度下能执行反馈修复，已超出单纯脚本路径证据；
它尚不证明RL能学会或稳定提升这种行为，也不证明八项工具因果上改善了推理。
综合准入未过，整体“先解决交互可学习性，再比较RL算法”的目标尚未完成。

收益与退化相抵；不能只展示inventory/windows的恢复路径而忽略windows总成功减少和
billing退化。下一步应静态对照配对候选及公开规格，确认编辑、反馈与资源因素，不新增
模型裁判，也不修改原始验证结果。

已完成全部6个discordant配对的离线阶段核对，另对两条windows失败候选逐行对照公开规格：

- 八项独有的3次成功，其四项配对均未提交任何Patch，最终仍为原始候选；这支持编辑
  执行路径差异的观察，不足以唯一归因于项数限制。
- 四项独有成功的windows_0配对中，八项`009`修正右端点并更新较新事件，但使用严格
  `timestamp > chosen[key][1]`，遗漏“相同时间最后输入胜出”。第8步公开测试已通过，
  最终独立判据失败。此为公开反馈覆盖不足和候选不满足规格的具体案例，不是工具格式问题。
- windows_1配对的八项`013`只修改窗口边界，aggregate.py与原始文件完全相同，保留
  first-seen缺陷，最终恰耗尽36k Token；不能推断单纯加额度必然补齐修复。
- billing_1配对的八项`029`没有提交Patch，并在SDK前因下一请求累计Token不足被拒。

判定依据为公开规格、冻结候选、Trace与原独立verdict；不是新增LLM judge标签。
语义审查范围仅上述两条windows候选，其余分类只描述可观察阶段，不扩张成全面根因分析。
后续新任务应检查公开测试对已知规格子目标和逐缺陷mutation的覆盖，保持独立验证输入
隔离；本轮公开/私有测试不修改，不用修补判据重新宣称该版本已通过。

## 截断及错误的代价

八项组有3条run出现4个截断项；四项组为0。4项均进入后续真实请求的工具消息，
并在下一次成功Patch之前通过read_file/read_files完整补读。这是可观测补读路径，
不能推断模型语义上注意到了截断，也不把正常补读算作无效动作。

离线9次请求原型曾预示7次可接受、其中6次截断；真实轨迹的请求选择已经改变，
不能把离线7次当成模型本轮“挽救”的7次调用或用它预测成功率。

八项组消除了本轮9次同类超项拒绝，但仍有12次路径拒绝；四项组为9次。
两组总invalid_arguments分别11与2，除批量项数外还包含其他参数错误，未知工具分别1与0。
工具错误包括有价值的失败测试，不能直接归为Harness缺陷；语义工具选择准确率未测。
完整读取的重复代理为0/122与5/127，未核验语义必要性，不宣称5次都是浪费。

## 阶段决策

H3按原门槛结束，不启动新的RL、GRPO/GSPO比较或第四轮工具校准，不自动再增路径数、
输出或Prompt。默认四项模式不变，八项保持显式实验选项，不因消除参数拒绝就升级默认值。

本轮3个四项-only与3个八项-only配对已离线核对，保留实际修复、漏改、参数与预算证据。
下一步只离线检查新家族任务的公开反馈覆盖、有效分组信号条件，并核算完整训练/留出比较资金。
不能反复在相同开发集挑配置以追求正差，也不能绕过原门槛给新训练换标签。
若需新研究问题或预算，应先形成独立、可审查的协议，旧H1/H2/H3全部结论保持冻结。
