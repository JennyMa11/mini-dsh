## 结论与实际训练量

本轮具备多轮反馈及非零训练信号，固定 80 条轨迹全部完成，但**没有观察到 RL 成功率
或单位成功成本改善**。这不能证明 Harness 太简单，也不能证明换算法即可解决问题。

Readiness 16 条、训练 32 条、配对测试 32 条全部保留，没有删失败或补采样。模型为
Qwen3.5-4B、LoRA rank 16、seed 17、学习率 1e-5、G=4。本轮是 native PPO loss 的
简化 GRPO：二值成功 Reward、组内减均值，不做标准差归一化、不加 KL、clip=0.2。

Readiness 成功 5/16、混合奖励组 3 个；match_rank、table_join 有独立反馈恢复证据，
原门槛通过。训练成功 5/32；8 组中仅 **3 次真实 optimizer update**，其余 5 组全零
奖励、零 Advantage，跳过更新。训练成功不能证明泛化收益。

两次执行进程均正常 exit 0，执行耗时合计约 41.5 分钟，不含等待结算。初始权重
实际下载核对：496 个张量、248 个 B 矩阵，B 范数为零。最终权重首次审计因 API
checkpoint workspace 字段为 null 而拒绝下载；后续核对 owned run、checkpoint 的
run 关联、精确 sampler URI 和 owner/run 路径，确认归属后仅下载已存在的权重。
最终 archive 为 64,952,320 bytes，496 个张量、248 个 B 矩阵，B 范数 0.07978756，
相对初始 adapter 的 L2 差 0.08162914，**实际参数变化已确认**。没有重训、重新
export 或再次计提费用；原失败文件和回执保留。参数变化不等于任务收益。

## 配对评测

8 道生成式 held-out 任务，每题 2 个固定采样 seed。每对 Base/RL 使用相同 Harness、
工具、预算、判据及 seed，不按 test 选 checkpoint。训练有 3 个潜在任务家族，测试
有 4 个不同家族；这同时考察跨家族迁移，不是训练题复现，也不是 SWE-bench 结果。

| 指标 | Base | RL |
| --- | ---: | ---: |
| 独立判据成功 / 声明数 | 7/16 | 4/16 |
| Resolve Rate | 43.75% | 25.00% |
| 总 Token，含失败 | 397,981 | 372,332 |
| 全部 Token / 成功数 | 56,854 | 93,083 |
| 平均工具调用数 | 8.7500 | 8.8125 |
| 重复失败动作代理 | 0/140 | 3/141 |
| 无效参数或未知工具调用 | 1/140 | 0/141 |
| 工具执行错误 | 27/139 | 31/141 |
| 端到端 p50 / p95 | 28.00 / 41.72 秒 | 23.76 / 46.68 秒 |
| 测试采样保守估价 | 0.841 元 | 0.804 元 |
| 测试采样估价 / 成功数 | 0.120 元 | 0.201 元 |

费用只含测试采样，不分摊训练、存储或工程开销，不是实付账单。工具错误包括失败的
公开测试，不能全部归因于 Harness。端到端包括工作区/容器准备、Loop、候选采集
和独立验证，与 Loop 延迟单列。

成功率差为 **−18.75 个百分点**。8 题配对 cluster bootstrap，保留题内两次重复，
10,000 次、seed=20261107、nearest_rank，探索性 95% 区间为 [−37.5, −6.25] 个
百分点；按 4 个测试家族聚类的敏感性区间为 [−37.5, 0]。只有一个训练 seed、8 题、
4 个家族，不能将题级区间外推为普遍算法结论。Base 独有成功 3 对，RL 独有 0 对。

RL 总 Token 少约 6.4%，但每成功 Token 高约 63.7%，工具调用未减少，不能宣称
效率提升。中位延迟较低而 p95 较高，也不足以支持全面加速。

## 失败分布和证据边界

| 测试家族 | Base | RL |
| --- | ---: | ---: |
| record_diff | 0/4 | 0/4 |
| alias_resolution | 4/4 | 3/4 |
| greedy_packing | 3/4 | 1/4 |
| expression_pipeline | 0/4 | 0/4 |

两个家族全失败，另外两个家族出现退步，任务难度分布明显不均。不能利用这轮 test
反复改题、调 Reward 或挑 checkpoint；保留为冻结历史结果。

Base 有 1 条、RL 有 3 条被候选静态规则拒绝，其中各有 1 条语法错误，其余只确认
命中其他静态规则，尚未细分根因。静态失败属于预声明独立判据失败，保留分母；
32 条测试均有独立判据结果，但功能测试子进程实际执行分别为 15/16、13/16。
不得为了提高分数事后放宽静态规则。

全轮通用 Trace 的 unknown_usage_calls=12，均为实验包装层在请求提供商之前
拒绝 Token 预算触发。实际采样 start/return 证据完整，派生口径 unknown provider
usage 为 0。两种指标分别保留，不能把通用 Trace 数字解释为未知付费请求。
PyTRIO 缺少缓存遥测，默认缓存 Token 为零不能当作实测缓存未命中。

“有效更新少”“跨家族迁移困难”“预算终止影响表现”是待验证解释，尚无单变量
对照证明因果。当前证据不能证明更复杂的 Harness 必然改善学习。

### 三对退步轨迹的离线定位

选择规则是固定 16 对中全部 Base 成功、RL 失败的 3 对，仅作回顾性描述，不能以
这 3 对推定所有失败的原因。`regression-review-02.json` 保留逐步骤证据与输入 hash；
分析只解析已有文件，没有执行候选代码、重跑判据或改变原始成功标签。
这些描述标签是在查看轨迹后制定的探索性标签，未预注册。01 中标签时序字段措辞
不准确，02 单独勘误并保留 01 的 hash，不修改任何原始结果。

| 任务 / seed | 已观察到的分歧 | 对下一步设计的启发，尚非因果结论 |
| --- | --- | --- |
| alias_resolution_0 / 54405 | Base 用批量读取并完成两处修复；RL 逐文件读取，随后用被拒绝的绝对路径读取公开测试，再搜索，12 步终止且零 patch | 检查读取组织与行动时机，不先增加工具数量 |
| greedy_packing_0 / 54793 | 前 9 次工具及参数相同，第 10 步均修复容量比较；公开测试仍失败后，Base 第 12 步修复 first-fit 顺序，RL 第 12 步原样复测失败 | 重点检查失败反馈是否引发新动作；正常复测不能一概惩罚 |
| greedy_packing_1 / 54987 | 两策略前 8 步工具及参数相同；RL 第 8 步 snapshot 的全部可写文件与本对 Base 独立验证成功候选逐字节一致，随后两次改写 packing.py，删除 first_bin import，最终静态规则拒绝 | 检查过度修改和终止决策；不能将“更多 patch”直接作为正 Reward |

最后一例的中间版本**没有重跑功能验证**，这里只声明与已有成功候选的文件一致性，
不新增“中间成功”计数。AST 同时确认最终版本仍调用 first_bin，却没有对应 import
或本地定义。三条 RL 均因 step budget exhausted 终止；该现象不证明增加步数有益，
因为第三条已经显示后续动作可能破坏较好的候选。
