# 累计 ¥50 内的终点评测优先级调整

冻结时间及hash见`benchmark-results/trainable_agent/expansion-v2/budget-priority-amendment-02.json`。本调整在Pilot训练尚未结束、validation配对评测尚未开始、新test模型调用为0时登记。它替换本轮P之后“先延长60/120槽”的资源顺序，不提高累计50元，不更改已经运行的轨迹、任务划分、奖励或采样。

## 依据与选择

完整筛查支持任务有可解性与随机差异；新增Smoke确认实际权重改变。Pilot前18槽真实无缓存影子估价均值0.3599元/组，40槽训练外推约14.71元，加64条validation最坏5.12元约19.83元，均为假设预测而非最终账单。继续追加80槽训练显然难在剩余累计50元中同时保留独立test，追加20槽也会挤压test。

因此本轮以**完整40槽训练 + 64条配对validation + 条件准入的128条配对新test**为轻量主实验。60/120槽剂量扩展、独立训练seed及工具成本Reward臂推迟到本轮结论后的独立预算规划。原扩展规则仍可作为未来候选规则，`analyze_v2`产生的`allow_extension`仅保留为诊断，不在本轮自动触发训练。

## 冻结规则

1. 40槽全部完成、数值/训练Datum审计通过后，固定其最终checkpoint。不得选择中途最好checkpoint。
2. 完成Base/RL各16个validation任务×2次，即64条。validation无论提升、持平或下降，都使用相同test准入规则，不用它选择是否只报告有利结果。
3. 如全局剩余预算≥7.68元、无未知RPC且证据一致，开始完整128条新test：32任务×2次×Base/RL。0.06元/run为无缓存保守准入上界，不是平均预测或实际最低计费。
4. 新test模型、任务、Prompt、工具、步数/Token、镜像及判据与Pilot协议相同；唯一比较变量为初始LoRA与40槽最终LoRA。pair内同seed，顺序交替；初始LoRA路径来自本次Pilot，不能替换成plain Base筛查。
5. 若不足完整test额度，则test全体保持未运行，并报告资源准入失败；不挑题、删分母、用旧test替代或上调累计额度。
6. 若训练在40槽前因资源/安全/数值/未知请求停止，不能用部分训练冒充完整40槽；先结束并审计该停止，不自动打开test。

## 结论与后续边界

本轮仍是合成函数修复、单training seed的小规模研究；8个新test家族、每题2次不能替代多seed或真实仓库任务实验。报告所有失败消耗、独立验证、工具格式/执行错误分项、重复读取代理与覆盖、Token/成功、端到端时间及费用估价。LoRA变化只证明更新发生，不证明策略收益。

新test打开后不得再用其结果调学习率/奖励或延长同一训练并重测。未来扩展必须新冻结协议和未用于调参的任务；¥100/150仅为后续建议，未自动授权。重置卡不清零费用，不改变此上限。

## v2：根据硬Token限额收紧未来预留

v1的0.08元/run只是余量；v2在validation和test开始前，用实际源码证明：最多24000总Token、2048输出、8次请求。固定报价下连续费用上界为`(24000-2048)×1.49/1e6 + 2048×4.54/1e6 = 0.04200640`元；每请求输入/输出各向上取整至0.001元，额外上界`8×2×0.001=0.016`元，合计严格小于0.05800640元。因此未来test用0.06元/run、128条共7.68元作完整准入，仍有全局2元不确定额。以服务遵守请求max_tokens及冻结报价为前提；异常超量照实记账并停止，不能当作已知正常用量。

证据`final-test-bound-01.json`绑定模型适配层、Loop、Rollout和计费源码hash；v2 amendment绑定其hash及v1 hash。没有修改旧账本或历史记录。`evaluate_final_v2.py`保留原执行函数和配对顺序，仅增加上界证据校验及收紧未来财务预留；测试比较执行函数AST，并验证10000组确定性Token分配情景。validation仍用原入口的0.08元/run预留，不因未来test缩减其分母。
