| 训练信号 | 同题、同snapshot、同Harness的真实G4组有非零Advantage | 新反馈/新任务未测；两seed变化不能替代G4 |
| 学习收益 | RL相对同初始Base在未见家族上改善，并利用反馈路径 | 小仓库未训练，未验证 |
| 算法比较 | 匹配训练剂量、归一化和环境后比较不同目标函数 | 未开始；GSPO只有工程Smoke |

旧函数任务GRPO的正向点估计不能补认最后两项。当前8道开发题已经经过多轮分析，
仅用于问题定位和离线契约检查，不再承担独立测试集角色。

本草案不降低H1–H3门槛；新家族实验研究的是“固定工具条件下能否学习”，不是重新

## 2. 新数据规格：8家族、每家族2种跨模块缺陷

拟定train4家族×2变体=8题；test4家族×2变体=8题，不设置供调参的validation。
固定最后一个训练checkpoint评测，不在多个checkpoint或超参数间挑选最优。
以下为**待实现候选规格**；名称不同不自动证明与历史任务独立。

| split / family | 规格要点 | 代表性缺陷与必须覆盖的公开反馈 |
| --- | --- | --- |
| train / path_router | 按HTTP method和路径段前缀选最长匹配；精确method优先于同长通配，剩余同分保留声明顺序 | `/a`不能匹配`/ab`；最长前缀及method优先级分属匹配/选择模块 |
| train / dependency_batches | 按依赖图分批输出可运行节点；同批按ID排序，整批结束后才推进下一批；cycle报ValueError | 不能在同一批立即消费刚变ready的节点；重复边不增加入度 |
| train / table_join | left/inner join；相同key产生所有匹配组合，保持左表及右表顺序；left未匹配保留空右值 | 索引不能丢重复key；inner不能输出未匹配左行 |
| train / record_diff | 以唯一ID比较两版记录；分别报告新增、删除、字段更新；顺序由规格固定，输入保持不变 | 不能把删除字段当作None；更新不能只检查新字段 |
| test / alias_resolution | 多跳alias解析到实体；区分缺失目标与环；批量结果保持输入顺序，无输入修改 | 不能只跟一跳；多路径共享尾部不能误判为环 |
| test / greedy_packing | 稳定first-fit装箱；重量等于剩余容量允许放入，不能倒排物件或复用可变箱对象 | 不能改为best-fit；相等容量边界及箱对象所有权分属两个模块 |
| test / media_negotiation | media range按quality、specificity及声明顺序比较；q=0不可接受；无匹配显式返回None | 通配不能覆盖q=0的明确拒绝；排序方向/同分顺序正确 |
| test / expression_pipeline | 解析整数与`+ - *`、括号；乘法优先，加减左结合；非法输入报ValueError，不使用eval | 减法不可右结合；token消费必须覆盖完整输入，不能忽略尾部 |

每家族两变体共用同一规格/reference，但原始两个错误的组合不同，均跨至少两个逻辑
模块。保持与现有小仓库相近的调用链：约4个业务模块，加service和输入校验，公开
README/tests不可改。源码行数只描述复杂度，不靠无用docstring或包装器凑难度。
test规格公开给后续实现者是正常研究设计；任何模型筛查只能用train，不能按test表现
筛题、调整缺陷或决定训练停止。未运行任务仍保留在预声明清单。

离线构建阶段需先确认：AST规范化后没有直接复制历史reference/缺陷；共享主算法或
同源模板不能只改名后分到两个split。另按算法结构人工检查近亲关系，记录来源和范围。
本表没有构成预训练无污染证明；合成规格也不能保证无相似公开题。
若候选与历史家族过近，在任何模型调用前记录排除及替代原因、冻结新版本；不能因
模型失败后换题。当前候选尚未经过此审查，不能宣称数据集已就绪。

## 3. 公开反馈和独立判据的先验覆盖

每题固定如下最小矩阵，先写规格子目标和mutation，再写独立的公开与私有输入：

1. reference：公开/私有均通过；原始两个缺陷合并：公开/私有均失败。
2. 从reference逐个恢复两个原始缺陷：每个均被公开/私有拒绝。
3. 至少两个额外规格语义mutation：均被公开反馈发现，避免只修已知原bug的测试。
4. 常数解、忽略输入或返回原数据的明显错误解：按适用性声明、保留分母。
5. 边界、异常输入与输入所有权：每个适用子目标至少有明确检查，拒绝/超时单列。

公开测试提供足够可行动的信息，但不嵌入完整reference或隐藏输入。私有判据至少含
不同输入、组合边界和适用不变性；标记子目标覆盖与最终完整通过，训练仍只用最终
0/1成功奖励。禁止把已知私有反例塞进模型工作区，或由私有标签生成公开提示。
公开测试通过而私有失败是允许出现的泛化失败，不能据此改写旧Reward。

数据契约建议放在新`learning_tasks.py`：`LearningCase(task: MiniTask, split, variant,
criterion_version, public_feedback_version, source_family)`。`MiniTask`本身无需变更；
旧`development_tasks()`及`*_feedback_v2`保持原样。case ID形如
`learnability_v1_path_router_0`，与旧case显式隔离。每题另保存规格覆盖矩阵、fixture/
reference/public/private hash；模型只接收task.files和specification。

## 4. 先做一次固定readiness，不循环调工具

候选条件：初始4B零LoRA、原Prompt、显式`batch_read_eight`、5000字符总读取上限，
其余保持H3的12步/12工具、36k累计Token、6144单请求总长、3072总生成、单次1024、
180秒。选择八项是为了避免已观察到的六文件读取超项阻碍；**不是确认八项提高成功率**。
Full History、原生模板、temperature1/top_p1、现有权限/纯函数候选限制均保持。

只取4个train家族的variant0，每题G4=16条；任务和seed在首次模型调用前冻结，
每组同一initial policy且无更新；不删失败、不补采样、不据结果再改Prompt或工具。

拟定的研究可行性条件（待新协议冻结，不是旧门槛替代）：

- 四组全部完成且轨迹/真实Token/logprob/独立判据可关联，没有pending或未解释用量。
- 至少2/4个G4组为非全同Reward，且总独立成功在4/16–12/16之间；这是训练信号
  与极端难度筛查，不是自然成功率估计或显著性检验。
- 至少两个不同train家族出现真实的“修改后公开失败→后续采样→新Patch→私有通过”。
  首次候选只在控制面事后复评，私有结果不反馈给模型。
- 全部预声明预算与安全检查通过；成功不能抵消预算、安全或记录缺口。

未通过则报告本版本不具备足够训练证据，并停止付费阶段；允许离线错误分析，
不继续同一队列补题或修改门槛。模型readiness前也须预留后面的完整训练和测试，
不能先花剩余资金筛查、之后才发现无法完成闭环。

上述阈值只表示“值得一次小训练”，通过也不能称交互可学习性已解决。

## 6. 留出评测和学习结论

8题test×2seed×Base/RL=32条；每策略16条，4个未见家族。Base为同次主训练初始
snapshot，RL为固定最终snapshot；Harness、采样、预算及pair seed一致，运行顺序交替。
没有validation选checkpoint，也不按训练成功率决定是否报告test。仅因资源/安全/审计
不能执行的case保留完整声明分母，另报告未测项，不冒充完整配对结果。

主指标为独立成功率配对差；同时报告工具、格式、重复失败代理、Token总量及全部
Token/成功、E2E分位数与预算终态。使用family-cluster bootstrap保留题及重复，报告
仅4簇的局限；出现退化区间不解释为等效。小样本、不显著结果也全部保留。

反馈恢复比例另外报告“所有声明run”和“实际触发失败反馈机会”两个分母，避免只看
成功子群；首次Patch私有失败/最终通过的标签需事后独立证据。不能由工具格式改善、
非零权重或训练成功率推断反馈策略已经学会。

一次seed的正点估计只支持继续研究。若成功率差不为正，或提升只来自单一家族，
不进入算法效果比较。即使为正，也必须报告区间和效率代价，并在独立train seed及
新留出家族复核方向后，才将稳定交互学习收益标为有证据；本Pilot本身不保证达成。
未达到时继续定位数据、编辑或反馈瓶颈，不能自动换算法、增训练步数或大模型。

## 8. 后续算法比较的边界

GRPO先验证学习收益，之后才决定GSPO对照。现有GRPO使用assistant-token mean，
GSPO使用trajectory mean；直接比旧结果会把长度权重与ratio/clipping混在一起。
若研究ratio/clipping，需先匹配每轨迹权重，例如GRPO在轨迹内平均Token surrogate，
再对G条轨迹平均；GSPO对同一组assistant位置计算sequence ratio。保持Advantage、
初始weights/optimizer、任务顺序、G、学习率、采样、预算及终点评测一致。

该匹配目标当前尚未实现。通过SDK custom-loss实现时，已知路径含额外forward，
每臂可能需两倍训练Token预留；不能直接套用上表GRPO原生PPO的1.339元/组。
同时报告固定组数与实际计算/时间，不能把“同组数”称为同计算量。
后续比较需要新留出家族和单独完整预算，不承诺当前50元或一次Pilot能证明算法优劣。
