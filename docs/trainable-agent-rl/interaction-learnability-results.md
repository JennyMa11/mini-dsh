# 工具示例配对实验：交互可学习性仍待解决

日期：2026-11-07。原Prompt/追加工具示例的完整32条同期开发对照已结束；没有训练、
没有打开新test。机制准入未通过，当前目标保持进行中，不以工程链路通过替代模型收益。

## 实验与主要结果

8题开发集×2seed×2Prompt，16配对；两组均interactive，同一个已验证初始零LoRA策略。
任务、判据、工具、采样、12步/12工具、36k总Token、3072总输出、每次1024、6144上下文
及180秒不变。唯一改动是在system Prompt追加已评审示例；估计的是整段文本的效果，
无法分离内容、语言和增加上下文的影响。运行源码hash从头到尾一致，32/32全部保留。

32/32均有可判定结果；其中31条执行了私有候选测试，另1条在候选策略/语法检查阶段拒绝，
仍按预声明规则计失败。结果覆盖率不等于私有测试执行覆盖率，Loop正常结束也不等于修好。

成功率差+6.25pp，原Prompt-only成功1对、工具示例-only成功2对；按4家族bootstrap的
探索性95%区间为[-12.5,+25]pp（10000次、seed20261106、nearest_rank），跨零。
两次采样不是16道独立题，也没有训练seed重复。**尚未证明稳定成功率改善。**

示例组提交和修改后测试更常见，但格式拒绝仅少一次，总Token反而增加7.79%。
Token/成功的较低点估计主要受3/4次成功的小分母影响，不宣称工具效率收益。
延迟受服务与网络影响，也不据p50下降宣称稳定加速。

原Prompt本轮3/16与历史同配置1/16不同；没有把这种差异解释成模型升级或Harness收益。
这说明需要同期配对对照，不能拿旧A组与新B组直接对比。

## 关键诊断：反馈出现时经常已没有行动机会

从原始Trace精确重建378次真实请求，使用相同本地tokenizer逐Token核对全部prefix。
另重建4次未提交SDK的请求，独立计算当时的四项请求额度；没有发起新模型调用。

| 修改后失败反馈的观察 | 原Prompt | 工具示例 |
| --- | ---: | ---: |
| 有公开失败测试的run | 3 | 7 |
| 其中仍获得后续真实采样 | 1 | 2 |
| 所有失败反馈后均无后续真实采样 | 2 | 5 |
| 曾在第12步才得到失败测试 | 3 | 3 |
| 失败测试后成功提交新Patch | 0 | 0 |
| SDK前因Token预算拒绝 | 0 | 4 |

10条出现修改后失败反馈的轨迹中，7条之后没有真实采样机会；有机会的3条也未成功提交
新的Patch。因此资源限制是明确障碍之一，决策和格式问题仍存在，不能推断增加预算必然修好。

示例组4次拒绝均发生在第12步：已有消耗约31.7k–32.0k，下一次Prompt需约4.6k–5.1k，
超过36k累计额度。此时单次上下文仍有约1.0k–1.6k余量、输出总额度也未用尽。
**拒绝原因是累计Token不足，不是6144单次上下文太长。** 原错误码context_overflow和
Loop终态failed原样保留，报告不把它改写为另一种实测终态。

原Trace中这4条model_call_failed保留usage_known=false；独立的prefix/额度/账本检查
证明它们在SDK采样前就拒绝，没有新增provider请求或pending费用。此为派生证据，
不把原事件中的未知字段填零。所有实际提交的378次调用均有原始Token/logprob记录。

六条成功且有多次Patch的轨迹，首次Patch经独立复评失败、最终通过；但两次修改之间
没有公开失败测试。这些轨迹支持“多次修改路径可用”，不补认预声明的反馈恢复机制。
正配对差和2个示例-only配对满足部分准入，反馈恢复覆盖仍为0家族，故整体门禁失败。

## 阶段决策

H1只有弱的正向点估计，当前不能宣称交互可学习性已解决，也不启动新GRPO/GSPO比较。
下一项优先候选是减少读取回合：在受控工具中支持批量读取公开仓库文件，验证是否能在
相同任务及总预算下给失败反馈留出修改机会。先做内容等价、白名单和输出上限的确定性
验收，再冻结新的单变量Pilot与完整费用准入；本报告不把候选功能写成已实施。

读取次数减少不能自动判为推理能力提升，公开测试非零退出不能自动判为Harness缺陷。
新研究不在本队列补采样凑门槛；保持原门槛和所有负面结果。正式留出评测、Reward成本臂、
SFT与算法比较均未实施。下一轮应首先解决修复机会，不扩大核心Runtime功能范围。
