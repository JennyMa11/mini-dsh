# H3：固定输出上限，比较4路径与8路径批量读取

日期：2026-11-07，分支 `experiment`。决策见[ADR0039](../adr/0039-batch-path-limit.md)。
本协议在真实H3采样前制定；不改写[H2结果](batch-read-results.md)或其门槛。

## 依据及选择

H2两组均3/16成功，八题开发集尚无稳定交互收益。处理组9次Schema拒绝全部因请求
超过4路径；原错误消息已明确给出4项上限，不能假设此前没有向模型解释限制。
离线在原始任务文件上重放9次请求，可信driver改为最多8路径后：7次通过，2次仍路径
拒绝，7次通过中6次触发5000字符共享截断，文件快照不变。

因此仅选择“是否放宽路径项数”这一项：它可以消除部分不必要的参数拒绝，也可能
增加无效信息、补读和Context压力。结果未知，不预设降低拒绝就能提高修复率。
重放不是历史修改工作区的复跑，也没有产生模型新动作或成功率样本。

## 单变量及固定设置

| 项目 | 控制组 | 处理组 |
| --- | --- | --- |
| 标识 | batch_read | batch_read_eight |
| read_files路径上限 | 4 | 8 |
| 读取输出总上限 | 5000字符 | 5000字符 |
| 工具 | 两组均read_file/read_files/search_repo/apply_patch/run_tests | 相同 |
| Prompt | interactive + original | 相同 |
| 模型 | 同一初始零LoRA Qwen/Qwen3.5-4B、rank16 | 相同 |
| 队列 | 原8题×2seed，各16条 | 同case/seed配对，交替顺序 |
| 资源 | 12步、12工具、36k总Token、3072总输出、每轮≤1024、6144上下文、180秒 | 相同 |
| 采样 | temperature1、top_p1、top_k−1 | 相同 |
| 安全/判据 | 原固定镜像，1CPU/1GB、禁网、单Agent顺序；原任务与私有判据 | 相同 |

Schema除maxItems由4变8外完全一致；工具说明只有对应数字变化，系统指令不变。
干预同时包含路径上限及其声明，不分离数字语义与模型后续选择。
原默认single_read及四项batch_read不变，八项必须显式选择；可信Session配置决定上限，
模型不得通过参数覆盖它。容器只接受可信上限4或8，原真实路径、白名单和符号链接检查保留。
全部路径通过后才返回内容，非法整批失败，不自动拆分请求、不重试或补采样。

八路径不等于一次获得八个完整文件。逐项truncated及总truncated必须准确，后续文件可
空内容且标记截断；模型可以用原工具补读。两组信息访问权限相同，实际获得内容不保证相同。

## 离线验收与接口

- `BatchReadEight`继承四项Schema与重复项校验，仅改maxItems；额外字段、空列表、重复、
  非字符串及超过8项拒绝。默认Session不允许八项，八项参数不能自行设置更大上限。
- 同一真实容器测试八项请求仍共享5000字符，截断明确、文件未修改、patch数不变；
  错路径和符号链接整批拒绝。只读权限fs.read与原Tool Runtime链保持不变。
- 确定性完整Loop：两组先请求相同五个小文件；四项组收到拒绝后用合法分组补读，
  八项组直接读取，再读取剩余文件。两组最终观察相同全部公开文件，均经历公开失败
  测试、新Patch及独立通过；中间候选独立失败。合成Token只作为工程证据。
- 精确本地tokenizer检查两组16种首轮输入，四项组与H2处理组16个历史prefix逐Token
  一致，两组Token长度相同且加1024输出不超过6144；不宣称后续累计额度也相同。
- 评分、诊断与失败分类支持新phase；arm及实际batch_path_limit错绑必须拒绝。
  控制探针不是4/8两种上限、source过期、完整资金不足时，不连接模型或SwanLab。
- 所有修改在独立实验包；核心Loop/插件、安全及训练算法不变。新增selector为
  `--limit-study --batch-control <H3控制证明>`，控制proof显式包含两种path_limits。

源码集中于minirepo_tools/driver/rollout/studies/experiment/analysis、
`minirepo_limit_probe.py`、本地渲染/publish脚本及契约测试；旧工作流继续兼容。
任务门禁仍需原56项检查。源文件变化后重新生成绑定证据，不覆盖旧报告。

## 评价与出关门槛

主结果为独立成功率、配对差及discordance，完整32条分母保留失败、取消、预算终止和
未运行机会。四家族bootstrap 10000次、seed20261106、nearest_rank，区间仅作探索。
同一开发集已用于多个假设，选择偏差与多重探索必须公开，不将其当作留出泛化结果。

机制沿用H2前瞻性口径：成功批量读取早于某个已Patch候选的公开失败测试，之后成功
提交新Patch，最终独立通过；运行后私有复评失败时的候选也必须失败。允许第k个候选，
不要求只为第一次，不把私有结果反馈给模型，不把普通多Patch自动判为反馈修复。

开发出关仍要求三项同时满足：配对差>0；≥2个八项组-only成功配对；八项组有≥2家族
的上述机制代理。资金另外准入。仅通过格式、拒绝或脚本检查不等于可学习性已解决。

必须同时报告：实际批量使用run/调用/文件数；Schema、路径及格式拒绝；总/逐项截断、
可检查的截断后补读；修改及失败测试step、之后真实采样与新Patch；各终态/失败类型；
总Token及失败消耗、工具次数、E2E p50/p95、费用/成功。零分母null，未知用量不记零。
更少调用不自动等于更高效率，公开测试失败也不自动等于Harness缺陷。

## 资金及停止条件

唯一活动账本仍为expansion-v2/calibrated-budget.json，累计上限50元不变；当前保守占用
44.013元、可用5.987元、pending=0，含2元不确定性预留，最终实付未知。
无缓存固定报价下，沿用单run上界0.0870096<0.09元，完整32条预留2.88元，阶段cap3元。
名义总Token上限1,152,000、总输出98,304，缓存折扣不计。未租GPU、无梯度与新LoRA管理。
两组都提供批量Schema，实际费用可能接近或超过H2的2.094元，不能据历史平均降低预留。
若用满预留，剩余3.107元，不保证还能容纳后续RL及完整算法评测。

本机顺序32条按H2约19–37秒/条粗估约10–20分钟，Loop累计上限96分钟，准备与验证另计；
墙钟不是GPU小时。模型、网络或未知计费失败保留证据并按已有规则停止，不盲目重放。
不得根据中途成功率提前停采/补采，不缩小完整分母凑资金，也不自动提额或使用重置卡。

H3若仍未通过，先收敛工具契约和反馈路径的失败分类，不自动再增路径数、Token或Prompt。
若通过，也仅可进入新家族上的success-only RL Pilot设计与独立资金准入；算法比较还须
共同初始化/优化器、归一化、训练剂量和完整留出评测。只有目标全链路证据满足后才算完成。
