# H2：减少读取回合，验证反馈后的修复机会

日期：2026-11-07。依据[ADR0038](../adr/0038-batch-read-learnability.md)。
当前处于离线准备，真实模型对照未执行，没有新增训练。

资金更新：[四小时覆盖审计](pilot-hour-reconciliation.md)已完成，保守累计41.919元、
可用8.081元，仍为50元上限。下文1.979元及未准入为首次准备时点；完整32条现在
有2.88元容量，执行仍需当前源码和报价核对，不自动进入RL。

## 研究问题及依据

[H1 工具示例结果](interaction-learnability-results.md)为3/16对4/16，成功率差的探索性
95%区间跨零，失败测试后成功修改为0。10条获得修改后失败反馈的轨迹中，7条没有
后续真实采样机会；4次 SDK 前拒绝由累计36k Token不足导致，不能通过加大单次上下文解决。

H2 假设：在相同信息权限和总预算下，减少文件读取回合，能让失败反馈更早出现，
从而增加继续修改和最终修复的机会。此为待验证假设；脚本能节约回合不代表模型会使用。
同时检查“有机会但仍不修改”，避免把所有失败都归因于预算。

## 固定对照

| 项目 | 预声明设置 |
| --- | --- |
| 数据 | 原8题开发集，4家族各2变体；不增加或挑选任务 |
| 队列 | 每题2seed×2组=32条；同case/seed配对，组顺序交替 |
| 模型 | 同一 `Qwen/Qwen3.5-4B` 初始零LoRA rank16策略；无训练 |
| 控制组 | `single_read`：read_file/search_repo/apply_patch/run_tests |
| 处理组 | `batch_read`：原四工具，加可选read_files；不强迫调用 |
| Prompt | 两组均interactive、original；不追加工具示例 |
| 采样 | temperature=1，top_p=1，top_k=-1；沿用固定seed规则 |
| 额度 | 12步、12工具、36k累计输入+输出、3072总输出、每请求输出≤1024、上下文6144、180秒 |
| 隔离与判据 | 固定镜像digest，单Agent顺序；独立容器1 CPU/1GB、禁网；原公开与私有判据不变 |

唯一干预为是否提供可选批量读取能力。新增工具说明也会进入模型上下文，因此不是
“相同 Prompt Token 数”的比较，不声称分离了工具描述与批量执行本身的贡献。
历史原Prompt成绩不可替代本轮同期控制；重复采样不当作16道独立题。

## 工具契约与成本影响

`read_files({"paths":[...]})` 接受1–4个不同的仓库相对路径，禁止额外字段。
宿主先校验完整列表和白名单；容器再次检查路径、真实父目录、符号链接及文件大小。
全部路径通过后才读取，单次所有文件共享5000字符上限，保持现有总输出约束。
返回结构为：

```json
{
  "files": [{"path": "orders.py", "content": "...", "truncated": false}],
  "returned_characters": 123,
  "truncated": false
}
```

后续文件可能因共享额度得到空内容，此时必须 `truncated=true`，可用原工具单独读取。
批量调用仍按一次工具动作计账，同时单列请求文件数和返回/截断项数，不能把调用变少
自动解释为读取工作量下降或推理能力提高。只读 `fs.read` 权限，无任意Shell或隐藏文件权限。

成本可能降低的路径是减少模型请求和反复携带历史；成本也可能因新增 Schema、模型
不用新工具、重复读取或更多修复而增加。必须用真实 Token 和失败在内的消耗判定。

## 分层验收及指标

| 层次 / case | 触发、预期与禁止行为 | 检查与证据 |
| --- | --- | --- |
| C1 输入契约 | 空列表、超过4项、重复、非字符串拒绝 | `test_minirepo_batch_read.py`；不得执行进程 |
| C2 路径边界 | 越界、非白名单、符号链接整批拒绝 | 宿主NeverExecute与真实Docker；不得返回部分成功 |
| C3 信息等价 | 小文件内容与逐个read_file相同；不修改文件 | 容器快照前后相等，patch计数不变 |
| C4 共享上限 | 总返回≤5000字符；所有不完整项显式截断 | 大文件加后续文件，后续单读仍可用 |
| T1 脚本控制 | 原始相同公开文件、失败反馈、后续修改、独立通过 | 合成Token/零模型调用；两个候选分别私有复核 |
| T2 精确渲染 | 控制组16个历史初始prefix逐Token一致；两组首轮额度足够 | 仅本地缓存tokenizer；记录vocab/template与源码hash |
| T3 评分边界 | 第2次Patch失败后再修改可识别；迟到批量读取及原候选已通过不得满足机制 | 合成评分契约测试；不得作为模型效果样本 |
| F1 资金 | 完整32条不足时拒绝；不连接模型与SwanLab | 预算契约测试及准备目录admission；账本不变 |
| E1 真实任务 | 模型自行调用，独立验证最终代码 | 当前未执行；32条分母、所有终态和失败消耗保留 |

主要结果仍为两组各16次独立判定的成功率、配对差、discordance；按4家族整体bootstrap
10000次、seed20261106、nearest_rank报告探索性区间。不将退化区间解释为等效，不将
本开发集多次调试的结果作为泛化证明。

辅助指标包括：成功提交Patch比例、修改后测试比例、首个失败反馈step、反馈后真实采样
机会、反馈后成功Patch、反馈修复家族数、批量工具使用率/调用数/文件数/截断数、格式拒绝、
工具次数、Token、E2E时间及费用/成功。分母为零返回null，未知用量不填零；重复读取仅为代理。
机会诊断应从Trace绑定具体失败事件，检查其后是否有真实请求或成功Patch；必要时用
原始prefix和本地tokenizer复核预算。不能把最后一次工具成功当作所有故障已恢复。

H2 机制代理要求同一轨迹按顺序满足：

1. 成功执行read_files；随后某个已提交的第k个候选运行公开测试失败。
2. 运行结束后，在控制面复评第k个候选，其私有判据也失败；不把私有结果反馈给Agent。
3. 在公开失败测试之后成功提交新Patch，最终候选通过独立判据。

评分输出保留 `failed_patch_index`、`pre_revision_private_passed`、
`batch_read_before_feedback`，并对所有部分候选的复评另存sidecar。
允许k>1是新实验的前瞻性口径；旧H1“首次Patch”的准入不变。该顺序代理不能证明模型
因果上理解了错误，但比仅统计多Patch更接近研究行为。处理组没有实际使用批量读取的
成功仍计入主成功率，只不计入该机制覆盖。

开发出关要求：配对成功率差>0、至少2个batch_read-only成功配对、至少2个处理组家族
满足上述代理，另有完整资金准入。这是开发启发式，不是显著性门槛，也不自动授权RL。

## 预算和停止条件

继续使用唯一活动账本 `benchmark-results/trainable_agent/expansion-v2/calibrated-budget.json`。
当前保守占用48.021元，含2元不确定性；可用1.979元、无pending，最终项目实付未知。
本轮不租GPU、无梯度、无新LoRA管理操作；本地复用Docker及tokenizer缓存。

固定无缓存报价假设下，单run保守边界为：

`(36000×1.49 + 3072×(4.54−1.49))/1000000 + 12×2×0.001 = 0.0870096元 < 0.09元`。

最后一项为每请求两类别估价向上取整余量，不是提供商最低收费。
32条需预留2.88元，阶段cap为3元；当前缺口0.901元，拒绝付费执行。
整队列Token名义上限1,152,000，总输出上限98,304；实际用量依赖模型路径。
以H1约16–33秒/条的观察粗估串行32条约9–18分钟，非承诺；Loop累计墙钟上限96分钟，
容器准备与独立验证另计，不能把本机墙钟换算云GPU小时。

账单对齐只有在完整账期、工作空间归属、覆盖操作及重复计费排除均可审计时才释放预留。
不得用旧3.37元快照或工作空间余额重置累计消费。资金不足时不缩小32条队列，不新增
模型调用；安全失败或未知RPC立即保留记录并停止，不能按观察到的成功率提前停采或补采。

## 实施边界与下一决策

实现集中于 `experiments/trainable_agent/src/minidsh_rl/` 的tools/driver/rollout、
studies/experiment/analysis、脚本diagnostics/failure_review/publish及对应测试。
`minirepo_batch_probe.py`为脚本控制，`scripts/preflight_batch_rendering.py`为本地精确渲染。
默认single_read及旧Prompt入口兼容，主Runtime未加入任何训练能力。

先完成离线门禁与新准备目录，状态明确not_admitted；资金及全部源码绑定就绪后才可
考虑真实队列。模型数据进入SwanLab仅上传汇总白名单；原始Prompt、Token、Trace、候选、
判据、权重URI和凭据留在本地。脚本控制不上传成模型评测曲线。

若不通过，按四类失败决定下一项假设：不用批量能力、用后反馈仍过晚、有余量但不修改、
修改后仍错误。不混合改变Prompt/模型/预算来追求过关。若通过，先新家族success-only
GRPO Pilot和同Harness Base对照；再冻结匹配归一化的GRPO/GSPO比较，单独预算并保留
全新test及独立training seed。现有成功率、工程检查或这份协议均不代表完整目标已达成。
