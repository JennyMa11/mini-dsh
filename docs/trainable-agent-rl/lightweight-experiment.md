## 1. 收缩后的研究目标

先回答：**Mini-dsh 能否输出正确的多轮训练样本，并通过少量GRPO更新产生可测的行为变化？** 预算有余量时再观察工具成本奖励的方向。不承诺成功率显著提高，也不把单训练seed、小测试集的结果称为正式收益证明。

采用本机CPU/Docker执行任务、PyTRIO托管采样和LoRA更新；不租GPU、不用付费教师生成数据、不训练Reward Model、不跑SWE-smith/SWE-Gym，不增加SFT或Context消融。复用原Loop、权限、隔离、Trace与独立验证。新增的Token sidecar/Mask、评分和训练接线仍须实现；费用降低不意味着这些工程已存在。

基础模型沿用原方案 Qwen/Qwen3.5-4B，前提是账号支持、报价符合预算且具备可用工具协议。不要仅为“便宜”换成完全不会工具调用的模型。不可用时完成离线交付，另行冻结可用小模型的协议；本预算不同时开发本地GPU训练后端。

**默认先完成¥50核心版；只有价格核验后能把完整扩展队列装入累计¥100以内，才加入成本奖励臂。** 是否进入扩展仅依据资源与工程门禁，在查看测试集结果之前决定，不因某个结果好看才追加实验。

## 2. 任务集：40道研究题 + 4道工程夹具

- train16 / validation8 / test16，另4道smoke夹具。三套split按小项目家族划分：4/2/4个家族，每家族4题；共10个家族，禁止同源mutation跨split。
- 每家族3道易、1道中：单文件边界条件、输入校验，以及2文件接口/状态错误；不纳入跨大型仓库难题。
- 每个工作区3–5个文件，源码总量约100–250行，离线pytest通常≤2秒（须实测）；提供可见失败测试，隐藏边界/回归判据在新容器验证。
- 每家族至少2题需要查找第二个文件或依据测试输出定位；不强制“必须调用N次工具”才能成功。若真实轨迹大多只有一次修改，报告多轮覆盖不足。
- 原bug失败、参考修复通过、错误修复被拒绝、重复执行确定性、禁止改测试和验证器均须检查。仅将agent需要的fixture复制入容器，不能挂载包含隐藏答案的整个仓库。
- 可复用已有fixture生成/独立验证代码；已公开题只作为工程回归。不要随机划分共享模板的变体，也不使用test调Prompt/Reward。

这不是256题方案的无偏替代样本。结论只适用于冻结的轻量任务。4个test家族不足以证明跨仓库泛化。

## 3. 固定训练设置

| 项目 | 核心/扩展共同配置 |
| --- | --- |
| LoRA | rank16；服务实际alpha/target modules记录，不臆造可配置字段 |
| 分组 | 每槽B=1题，G=4条独立多轮轨迹；顺序执行 |
| 训练量 | 每臂20槽=80 rollout，单training seed=17；train16固定seed打乱遍历一轮，再取前4题 |
| loss | PyTRIO内置ppo，clip [0.8,1.2]，lr=1e-5；组中心化advantage，不除标准差；无reference KL |
| 采样 | temperature=1、top_p=1，Base与训练后评测相同 |
| 每run | 8 Loop步、8次工具调用、120秒、生成总量≤2048、单轮输出≤512 |
| Token | 单请求含输出≤4096，累计输入+输出≤24000；不足则预算终止，不截掉已生成事实 |
| Context | full history；Memory/Skills/额外修复/摘要关闭；所有策略相同Harness配置 |
| 保存 | 第10/20槽保存Train state及sampler；不开展checkpoint挑选 |

每轮实际输入P与真实生成C形成一个Datum，只训练本轮C；历史assistant和工具Observation为零mask。保留原Token/logprob，禁止从解析后的工具JSON反推。每个生成Token只贡献一次loss。该设计及训练reduction/恢复门禁沿用[完整技术方案](experiment-plan.md)，不能为省钱跳过。

全同reward组跳过更新但仍占20槽中的一个，不追加采样。每个槽完成整组后再更新；单组中policy snapshot固定。20槽是上限而非确保20次非零更新。

## 4. 两档实验与精确数量

### ¥50核心版：Base vs RL_success

1. 离线门禁：用4个工程夹具和确定性假模型检查mask、奖励、隔离与恢复，不产生服务费用。
2. Smoke：8条校准 + 2槽×1题×4=8条训练，共16条；训练用工程夹具和临时adapter，之后丢弃该adapter，主实验从Base重新初始化。校准可包含train题，不接触test。
3. RL_success：20槽×1×4=80条训练。每条reward为独立判据成功1，否则0。
4. validation：Base和最终RL各8题×1次=16条；只诊断，不选checkpoint或改参数。
5. 最终test：Base和最终RL各16题×2次=64条。

**总计176条rollout，其中88条有训练计算。** Smoke通过后冻结主实验队列；完整评测费用预留后才启动主训练。

### ¥100扩展版：追加一个RL_cost臂

从相同Base/LoRA初始化、相同任务顺序与训练seed另训20槽=80条。新增validation8条 + test16×2=32条，共额外120条；复用同一冻结Base评测，不能重复计作独立Base样本。

**累计296条rollout，其中168条有训练计算。** 三个策略：Base、RL_success、RL_cost。R_cost=`S × (1 − 0.1 × min(N_tool/8,1))`，成功为[.9,1]，失败为0；N_tool含无效/拒绝提议，解析失败成本口径预先冻结。相比原方案仅随工具上限把分母12改为8，两个训练臂其余配置一致。

不用同一组旧rollout训练两个已分叉的策略；两个臂各采自己的on-policy数据。额外一臂的价值是初步检查Reward设计，而不是增加训练seed的统计稳健性。

### 5.2 Token与费用公式

容量假设每条平均输入I=6000、输出O=1000，按每调用Datum计训练计算U=7000；相比原方案减半，依赖小工作区、短工具输出及较短交互，必须经Smoke校准。被mask的prompt仍有计算/计费成本。

| 档位 | 总R | 训练R | 输入M | 输出M | 推理合计M | 训练计算M |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ¥50核心 | 176 | 88 | 1.056 | .176 | 1.232 | .616 |
| ¥100累计 | 296 | 168 | 1.776 | .296 | 2.072 | 1.176 |

`C = I_M × p_prefill + O_M × p_sample + U_M × p_train + 附加费用`，无缓存优惠假设。缓存输入是输入子集；失败消耗与概率重算额外加入，不把训练mask有效Token当计费Token。

只做敏感性说明：沿用旧文档**假设而非报价**的1/4/4元每百万Token，核心约¥4.22、扩展累计约¥7.66；加30%余量约¥5.49/¥9.96。若真实单价整体为假设5倍，则约¥27.46/¥49.82；如果长度也翻倍，则约¥54.91/¥99.63，核心已超50。可见价格与轨迹长度必须同时核验，不能引用最低情景保证低价。

以上均不保证最大长度队列可装下：每run24000 Token的名义总上界为4.224M/7.104M，还须计训练及附加项。当前建议推理额度核心2M/扩展累计3.5M，训练计算额度1M/2M；先到Token、现金、时间任一限额即停止，未执行行保留。

### 5.3 防止跑完训练却没钱评测

开跑前按真实报价做静态准入；Smoke之后用实测逐run输入/输出、Datum计算量、服务账单和上侧长度情景重新预测。先锁最终评测资金，再分配训练额度；逐请求预留最大可计费输出及已知输入，训练RPC也预留计费上界。账单滞后时按已确认+已提交最坏费用计账，不能只看后台当前余额。无法界定单次计费上界时，不承诺硬封顶，停止提交并核对服务规则。

主训练从20槽降低为10槽只能在主训练前、未看test时冻结新配置，报告实际槽数；两个Reward臂必须同槽数。不允许第一臂20槽、第二臂因缺钱只跑10槽却声称只改Reward。若扩展资金不足，只完成核心版。

## 6. 时间、工程投入与停止条件

预计每条4次模型调用；假设输出20–60 tok/s、输入500–2000 tok/s，加工具/容器/RPC5–15秒，则约25–80秒/rollout。核心纯rollout约1.2–3.9小时、扩展约2.1–6.6小时；再加训练、保存和初始化，预算墙钟核心≤8小时、扩展累计≤12小时。远端排队未知，按Smoke重估，超时即停；这不是吞吐实测。

任务容器继续1CPU/≤1GB、禁网，主机控制面另占内存；无本地GPU要求。日志建议≤1GB、镜像缓存≤10GB，禁止为节省磁盘删除原始失败证据。首次从当前代码搭建接线及判据估计仍需4–7人日；可先交离线门禁，不能把¥100理解为包括开发人工成本。

立即停止：mask/logprob错位、Secret泄漏、未授权副作用、孤儿进程、判据篡改、NaN、未知更新状态。Smoke不足以形成至少一个混合成败group，或合法工具调用率<80%，不进入训练，先修协议/数据；不能边跑边花钱碰运气。主训练连续10槽无非零advantage就停，保留零信号结论。

## 7. 评测与可交付结论

主指标是16题×2次独立验证的single-attempt resolve rate，不能报告成best-of-2。并列工具提议/执行次数、无效调用比例、相邻重复失败比例、Token、E2E耗时、全评测成本/成功数（含失败花费；零成功为null）。失败、预算退出、未运行和未知验证全部保留完整分母与coverage。

逐任务配对Base/RL，列每题两次结果及4个家族结果。提供探索性的家族cluster bootstrap差值区间（10000次、固定seed），明确只有4个cluster和1个训练seed，区间不稳定；不据此证明泛化或稳定提升。32次测试集任务运行中的一次通过对应3.125个百分点，不能把几次成功的差异包装成可靠收益。

成功的交付包括：①完整可审计闭环；②Mask/Reward/恢复和安全证据；③冻结队列下Base/RL配对结果；④实际账单和Token；⑤是否值得追加预算的建议。没有提升也交付负结果。成本Reward仅报告成功率和工具数的联合方向，不在这个规模宣称“成功率不降”的非劣效结论。
