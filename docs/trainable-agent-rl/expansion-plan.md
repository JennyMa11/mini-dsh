## 3. 先修预算控制，再扩大队列

建议新增实验层`cost_model.py`、扩展`budget.py`，不改核心Runtime。旧`core-budget.json`只读保留；新账本必须引用旧账本hash及账单核对记录，累计历史消费只计一次，禁止通过新文件把历史费用归零。

新费用状态分别记录：

- `estimated_unbilled`：实际输入/输出及训练计算量×已核验单价，Decimal保留至少6位小数；**若服务确有逐请求最低收费，则仍按真实规则计费**。缓存未知按未命中计，不猜折扣。
- `pending_reserved`：提交前按该RPC最坏Token和训练padding预留；结果未知继续占用，不自动释放或重试。
- `billed_confirmed`：已核对账期、workspace与操作范围的消费；不能把同一操作同时累加到估价和已入账。
- `uncertainty_reserve`：未验证的收费、存储、账期差异预留。若无法把workspace账单归属本实验，则该账期总账与对应估价采用较大覆盖额并保留歧义，不能重复累计同一批调用。

准入：`已确认历史 + 当前未入账保守估价 + pending + 下一完整group/评测块上界 + 不确定预留 ≤ 累计预算`。先验收重复结算、旧账本迁移、未知RPC、跨小时账单、缓存未知、倍率变更与超额停止契约。原先15元固定“评测预留”改为剩余完整评测队列的动态预算；做不到时先按旧控制器执行能装入的小Pilot，不提高旧limit绕过。

先做一个独占时间段的16次小模型请求对账（计入A阶段配额），核实取整单位及计费延迟；账期未结算就等待或保留预留，不因“暂未扣费”扩张。下一完整阶段预估不足以完成时不启动；已开阶段触顶则保留未运行分母，不只报告跑完的题。

## 4. 任务集v2与Harness冻结

新增96题，24个独立来源/语义家族，每家族4题：train48（12家族）、validation16（4家族）、test32（8家族）。旧40题全部降为历史/开发回归，尤其旧test已用于故障分析，不再承担后续确认性测试。

目标train难度分布约25%易、50%中、25%难；用Base在train/validation的128条筛查（64题×2）估计整体可解性，**两次抽样不能精确估计单题成功率**。结合静态复杂度、错误类型与family层表现判断，不按两次全失败删除所有难题。test不做模型筛查；只运行bug/reference与预声明错误解探针，固定后封存。若train全成功组仍偏多，主训练前修订任务版本，保持所有筛查费用及被替换记录；test随语义家族重新检查隔离。

扩展任务首先覆盖同一纯Python能力边界：输入类型、嵌套边界、不变性、异常处理、关联数据结构等；让读取测试与实现、执行失败、修改、复测均有实际用途。当前独立验证器只支持单个implementation.py及包装入口，因此此版本仍**不能声称真实多文件项目修复**。真实2–3模块修复、SWE-Gym/SWE-smith作为单独环境升级，需新的candidate bundle、验证器和基线，放在本轮之后。

A阶段工程对照固定24个开发case（可使用旧研究题作开发）、旧/候选Harness各一次，共48条；一次只改一个明确缺陷，例如编辑结果反馈或已确认协议解析错误。首先离线检查所有格式拒绝原始Token：输出是否截断、JSON本身无效、合法原生工具是否被误拒；不自动给错误工具JSON“修成对的”再训练。`512→1024`输出长度是独立预算消融，不能与编辑工具变化合并。若A阶段仍没有可靠改进，保留原Harness，不强行加新工具。

A完成后冻结唯一Harness v2；所有Base/RL使用它。若改变Harness，历史Base 78.1%只能作背景，必须重新跑新Base。LoRA从同一基础模型新建，旧最终LoRA只作为历史artifact，不悄悄接着训练以混入旧数据/优化器状态。

P进入E的候选收益门槛：val较Base至少多成功2/32，或全部失败消耗计入的Token/成功下降≥10%且成功数不下降。只作资源分配规则，不作统计显著性宣称。如果未达门槛但有效组≥12且数值稳定，可预声明**仅一次**延长到60槽检查（包含在E额度）；60槽仍无方向就结束，报告否定结果，不为追求阳性继续改lr。预先声明这些数据依赖停止规则；停止时不冒充完成120槽实验。

120槽预计约48–96次有效更新（假设有效率40%–80%，不是保证），相比原8次足够检验更大训练剂量。保留0/20/40/60/120槽的状态/权重索引；其中20槽不额外评测，40/60/120共用val，预先承认重复查看。GRPO每组仍仅一次更新，禁止对旧rollout反复多epoch以便宜增加“步数”。模型、采样和lr维持原值；更高lr只在以后独立实验中研究。

## 6. 成本Reward的最小可比较设计

优先级：A→P→E→R，C低于独立seed复现；如果研究重心是工具效率，可在打开新test前选C替代R，不同时铺开超出预算的臂。

固定唯一权重：`r = success × (1 − 0.1 × min(tool_calls/8, 1))`。失败始终0，成功奖励在[0.9,1]，不因少调用但失败而得到正奖励；不奖励“未运行测试”。这是**轨迹级排序**，并不能保证模型总体成功率不下降，也不是硬约束优化。

组内仍中心化、不除std；全成功组可能产生微小成本梯度，全失败仍零信号。它的有效组率预计高于R0，必须同时报告有效更新数与实际训练Token；固定采样槽数的比较估计Reward设计整体作用，不能把收益完全归因为工具惩罚本身。若要匹配有效更新数需另做消融，不在这笔预算内临时补采样。

验收目标：成功率差≥−5个百分点，同时总Token/成功下降≥10%，工具调用下降作为次指标。只有成功率非劣区间下界高于−5个百分点且成本区间支持下降，才宣称可靠效率改善；32题通常不足以达到该精度，未达到时写“趋势/不确定”。不把多种lambda扫出最优结果当预设实验。
