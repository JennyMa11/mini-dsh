## 1. 计量边界

一条 rollout 是一个完整多轮任务，不是一个模型请求。设 R 为 rollout 数，平均每条 I=12000 输入、O=2000 输出（多轮重复历史输入已计），U=14000 为每条训练轨迹按调用Datum累计的前后向输入Token估算。这个 U 不是 assistant loss token 数：被mask的上下文仍需前向且可能计费。平均6次模型调用只是容量假设，必须由Smoke替换。

每 run 硬限制：12步、12工具调用、300秒、累计输入+输出64000、总生成4096、单请求含输出≤8192。Loop现有Token预算允许一次响应后的可观测超量；实验调度器另做每次请求最坏成本预留，保留所有超量，不能靠截掉日志实现账面限额。未知用量停止后续付费提交并对账。

训练rollout `R_train = 臂数 × training_seeds × 槽数 × B × G`。这里 B=2、G=4；全零优势仍占槽，不按“有效更新数”追加rollout。

## 3. PyTRIO主路线的费用

PyTRIO为托管服务，本机运行CPU控制面、Docker任务与日志，不需要租GPU；云端GPU型号/显存/占用未核实，不报告虚构GPU小时。官方模型/价格页面在本次文本访问未返回可用报价，**没有可验证的当前单价**。Lab历史实验账单不能直接套到Coding任务。

按实际报价代入：

`C_service = I_uncached/1e6 × p_prefill + I_cached/1e6 × p_cache + O/1e6 × p_sample + U/1e6 × p_train + C_checkpoint + C_storage + C_other`。

I_cached是I的子集；首轮按零缓存收益预算。失败/重试的计费全部加入。保存、重算logprob、padding、最小计费单位及税费需要在Smoke核验。

为便于判断量级，下面仅用**人为情景单价** `p_prefill=¥1/M、p_sample=¥4/M、p_train=¥4/M`（不是PyTRIO报价），无缓存、无附加费：

## 4. 本地GPU备用路线

仅当托管路线不能满足能力/预算时评估，不同时为两个训练后端付费。备用模型 Qwen2.5-Coder-1.5B-Instruct，冻结BF16基座、LoRA rank16，建议alpha32/dropout0及attention+MLP线性层（需选定库后核验模块名）。microbatch=1、gradient checkpointing、串行采样与训练，8K上下文。此配置是待实测假设，不是PyTRIO可传参数。

1.5B BF16权重约3GB；训练还需激活、LoRA梯度/优化器、logits、临时buffer与采样KV。先用24GB卡短序列测峰值，8K或服务共驻OOM时优先48GB或分时卸载，不能把权重大小当训练显存。4B基座权重约8GB，完整训练峰值仍未知；本方案不承诺24GB可容纳4B多轮训练。不要为节省一次OOM改成QLoRA并继续与原BF16基线比较。

[Runpod官方价格页](https://www.runpod.io/pricing)，2026-11-06读取：A40 48GB $0.59/h，L40S 48GB $1.09/h，A100 PCIe 80GB $1.79/h；具体库存、地区及附加磁盘税费需租用时核验。这些是备选价格，不代表本次租用。

时间敏感性模型（顺序执行）：`T = R × (O/v_decode + I/v_prefill + t_tools_and_verify + t_RPC) + T_train + T_checkpoint + T_setup`。

容量假设 v_decode=20–60 tok/s，v_prefill=500–2000 tok/s，工具/独立验证/容器/RPC合计10–30秒，则单条约50–155秒；这不是设备benchmark。新增训练更新、checkpoint和初始化后估计：Smoke 1–4h、MVP 4–16h、Pilot 14–48h、Formal 100–320h；全阶段119–388h。托管排队可能更慢，实际以S0替换。

若备用路线整个时间都占租GPU，A40约$70–229、L40S约$130–423，另加磁盘/网络等；Formal单阶段A40约$59–189。美元报价与人民币上限比较需运行日汇率，不编造固定换算。可以把CPU测试期间释放GPU，但重新加载与实例最小计费需计入。不能把上述备用费用再加到主路线情景费用后称为必需总额。

## 5. 本地CPU、存储及人工成本

本机CPU做离线契约/数据准备；任务容器每次1CPU/≤1GB，顺序一个agent；验证在agent退出后另建容器。控制面/Docker VM额外预留4–8GB主存，日志存储10–20GB、镜像缓存20GB上限，实际峰值在Smoke记录。GPU服务的RAM不是任务容器的1GB额度。

7808条rollout在每条原始日志+数组0.5–2MB的假设下约4–16GB；Token ID/logprob可压缩，Trace和原始采样不丢弃。只保存每5槽Train checkpoint和阶段末评测权重，按服务可恢复性制定保留期，先确认删除策略，不自动删审计证据。

人工预计13–24人日（分阶段估计之和），不是现金报价：任务编写/判据审查可能比算力更贵。若只能投入数天，止于MVP，不把任务规模压缩后仍称Formal。没有额外调用大模型生成数据的默认预算。

## 6. 停止条件与成本报告

任何Secret泄漏、未授权副作用、进程清理失败、mask错位、验证器可篡改、NaN或policy身份混乱立即停止。连续10槽无有效信号、持续服务错误/未知用量、阶段额度不足以容纳下一完整组时暂停；已提交在途请求尽量取消，实际消费全记账。

每阶段输出 declared/attempted/completed/verified/unknown 数量、实际Token、报价版本、费用估计及账单差额、耗时分解。每成功任务成本分为：①评测全队列成本/成功数；②(训练+验证+评测)/评测成功数，并注明摊销范围。失败花费保留；无成功为null。流程跑通且没有性能增益仍是可交付结果。
