# Harness 实验 v1：执行结果与限制

日期：2026-10-03。依据[冻结协议](harness-study.md)，在原生 Linux/arm64、1 CPU / 1 GiB / 128 PIDs、无网络的候选和验证容器执行。旧 public-lite 基线保持原样。

**功能验收通过，机制对任务成功率的收益尚未得到证明。** 20 个功能 case 全部通过；六道公开题均通过 gold-pass / buggy-fail 门禁；所有已运行的机制刺激符合预设条件。但 8000 Token 的单次预算不足以支持这轮历史/日志下的完整修复与检查流程。

| 功能证据 | 结果 | 证据 |
|---|---|---|
| 正常路径 / 预算 / 故障 / 安全 | 8/8、4/4、4/4、4/4 | 固定 pytest 节点、JUnit、预期/禁止行为清单 |
| 原生容器隔离 | 通过 | 实际 loopback 对照、拒绝外部连接、无默认路由、cgroup 限制、无挂载/socket |
| 独立验证器 | 六对通过 | 原始公开题参考实现通过，错误实现失败；隐藏测试只在新验证容器注入 |
| 单变量与刺激门禁 | 三组 A/B 均通过 | 配置字段差异、实际日志截断与诊断保留、不同参数的三次真实文件读取失败 |
| 事实完整性与凭据保护 | 通过 | 采样结束时源码/门禁哈希未变，515 个输出文件中实际密钥匹配为零；不记录密钥值 |
| 离线重评分 | 一致 | API 调用 0，变更评分行 0；原 Trace 与报告不覆盖 |

选定 24 次，实际执行 20 次；最后一个在途请求将总量从停止线以内推到 **243146 Token**，超额 **3146**，剩余四次 JavaScript 恢复组运行保留为 `not_run`，没有补跑。未知 usage 为 0；失败和在途超额均计入总量。

- 输入 235701，输出 7445；缓存输入 155392 是输入的子集，不另加一次。
- 真实 API 调用 48 次，固定刺激模型响应 20 次（零 API Token）。
- 总步数 68，总工具调用 88；这两个数包含刺激。已执行运行平均 3.4 步、4.4 次工具调用，中位运行时长约 3.15 秒。
- 独立候选测试通过 **5/24 个选定运行**，或 **5/20 个已执行运行**；全部 20 次终态都是 `budget_exhausted`。
- 约束内成功 **0/24**。不能用候选测试通过替代预算合规或正常完成。

Context 在四个配对均触发压缩并保留关键约束，输入总 Token 减少约 **39.1%**。两种变体都在第二个模型请求后累计超过单次预算：已执行读取，但后续修复请求没有执行。这个结果支持当前条件下的输入缩减，不支持成功率提升。

Output 两种变体均保留头/尾诊断，B 确实截断。A 首个真实模型请求就超过预算，B 能继续执行更多动作，输入总量反而增加约 **10.9%**，总 Token 增加约 **12.9%**。B 有一个候选修复通过，但所有最终诊断答案判据失败、全部预算不合规，不能宣布“节省 Token 且保持质量”。

Recovery 的两个 Python 配对中，B 在第三个等价错误处发出恢复提示，A 没有该错误聚合提示；两侧各两个候选修复通过。严格“五次工具内有效行动＋public smoke 成功＋全测试通过”的恢复结果为 **0/2 个实际机会**（每侧），因为窗口内未执行 public smoke；后续请求被 Token 预算阻止。剩余 JavaScript 配对未执行；无法得到跨语言恢复收益结论。

本轮每组最多四个配对，且受到预算删失，不报告显著性或通用排名。`valid` 配对字段只表示两侧已运行且刺激触发，不能解释为有足够预算证明任务收益。输入估算是字符启发式，不是模型 tokenizer，也不能保证实际 API Token 不超出估算。模型版本快照与 seed 未采集，null 不代表服务一定未返回版本信息；temperature 0 不保证逐次输出一致。

后续 v2 应先用这轮保存的 API usage 校准估算/刺激大小，让首轮观察、修改和 smoke 都有可执行预算，再减少任务数或调整每次预算以控制整轮 Token。v1 事实保留；本轮没有追加 API 请求、选择性重跑、改题或更改运行默认配置。

产物在 Git 忽略的 `benchmark-results/harness-study/v1`；离线一致性视图在 `benchmark-results/harness-study/rescored-v1`，补充原报告哈希校验后的视图在 `benchmark-results/harness-study/rescored-audited-v1`。独立报告、逐行配对、Trace、候选、验证收据、源码快照、审计哈希与无密钥值的扫描结果均保留。

实验完成后额外加入了“原报告内容被修改则拒绝重评分”的回归测试与检查；固定采样使用的源码仍保存在 reproduction，修复未重跑任何真实模型任务。
